# 會計與主檔快取策略

**版本**：v1.4  
**最後對照程式**：2026-11-20（Asia/Taipei）  
**關聯**：[`15_會計系統模組規格書.md`](15_會計系統模組規格書.md)、[`19_HUB與會計全域身分傳承.md`](19_HUB與會計全域身分傳承.md)、backend `accounting-gas/SPEC/ACCOUNTING_MASTER_DATA_SPEC.md`

一句話：會計選單把「全公司廠商名冊」存進這台瀏覽器，最多 3 天；後端另外用一把最多 6 小時的共用暫存，避免每人每次都把整張廠商表掃過。

---

## 1. 快取原則（定案）

使用者少、主檔不常變，採 **「TTL 盡量長 + 自己改過就立刻改快取那一筆 + 有快取時 24 小時 SWR」**。

| 原則 | 白話 |
|------|------|
| **長 TTL** | 廠商、案場、會計主檔包等不常變的資料，前端可存 **3 天**；後端 GAS 暫存最長 **6 小時**（平台上限） |
| **寫入即更新** | 新增／修改主檔成功後，**優先就地改快取裡那一筆**（patch）；改不到才整包清掉，下次再完整重抓 |
| **讀取 SWR** | 有快取且未過 3 天 → **立刻顯示**。主檔包裡**已經有廠商**時，現行程式**不會**在 24 小時後背景重抓，要等 3 天過期、人或頁面強制重載。只有快取還在、但廠商是 0 筆時，超過 24 小時才背景重抓 |
| **背景重抓（SWR）** | HUB 員工／案場／班表、會計列表仍依各節。會計主檔包見上一列，**不要**再寫成「有廠商也 24 小時背景更新」 |
| **不 cache 敏感資料** | 薪資、個人出勤（規劃中）預設不進 `localStorage`，或僅 `sessionStorage` 極短 TTL |
| **GAS 與前端分工** | 6 小時以上的「長快取」放瀏覽器；GAS 只暫存「跨試算表讀取很貴」的路徑（員工權限、案場 map 等） |

**決策背景（2026-06-20）**

- 案場 map、員工權限：GAS 拉滿 **6 小時**
- 廠商、案場（HUB／會計表單）：**3 天**
- 會計 bootstrap：**3 天**（≥ 使用者要求的 24 小時）
- HUB 當月班表：維持 **7 天**（與案場／廠商分開，變動頻率不同）

**身分與 operator 傳承**（快取以外）：見 [`19_HUB與會計全域身分傳承.md`](19_HUB與會計全域身分傳承.md)。

## 2. 儲存層級

```
┌─────────────────────────────────────────────────────────┐
│  瀏覽器 sessionStorage   ← 會計 bootstrap（同分頁、依 userId）│
│  瀏覽器 localStorage     ← HUB 員工／案場／班表              │

│  GAS ScriptCache         ← 員工權限、案場 map、LINE 暫存…   │

├─────────────────────────────────────────────────────────┤
│  Google Sheets           ← 真實資料來源                     │
└─────────────────────────────────────────────────────────┘
```

**全域常數**

| 常數 | 值 | 檔案 |

| `GAS_SCRIPT_CACHE_MAX_SEC_` | 21600（6 小時） | `config_.js` |

**備註**：`accounting_bootstrap` **有**後端共用暫存（上表第 7 列）。暫存命中就直接回，**不再讀表、也不補欄位**。沒中、或剛被清掉，才掃廠商表。瀏覽器那份仍可放到 3 天，後端最長 6 小時。

**已知問題（不要當成正確設計）**：權限 2 與權限 3 共用 `acct_bootstrap_v1_staff`。權限 3 才會附上「合成的 LINE 綁定列表」；權限 2 的那包沒有這份列表。誰先打開，6 小時內另一種權限就拿到同一包。權限 3 若拿到沒有綁定列表的那包，廠商名冊會顯示「尚無綁定」，即使廠商列上其實有 LINE。這台瀏覽器接著把這包存 3 天，而且因為已經有廠商就不再背景重抓。見 §7。

## 4. CODING 前端快取一覽（會計相關）

### 4.1 會計 bootstrap（主檔包）

| 項目 | 值 |
|------|-----|
| **模組** | `AccountingCache`（`shared/js/accounting_cache.js`） |
| **儲存** | 記憶體，再加上 `sessionStorage` 與 **`localStorage`（子頁才能看到外框已載的名冊）** |
| **Key** | `tanxin_accounting_bootstrap_v6:{userId}`（舊的 v1～v5 載入時清掉） |
| **TTL** | **3 天**（`AccountingMasterData.TTL_MS`） |
| **SWR** | 常數仍是 24 小時（`AccountingMasterData.SWR_MS`）。**現行**：快取裡廠商筆數 &gt; 0 → 直接用，**不**背景重抓。廠商是 0 筆且超過 24 小時 → 先顯示、背景重抓 |
| **常數檔** | `shared/js/accounting_master_data.js` |
| **載入** | `AccountingCache.load(session)`。沒有未過期快取時，子頁先等外框最多約 60 秒；等不到才自己打。單次後端等待最多 **120 秒**，失敗自動再試，最多 **3 次** |
| **強制重載** | `AccountingCache.load(session, true)`。廠商名冊在「自己這包與瀏覽器裡都沒有廠商」時也會強制重抓 |
| **CRUD 後更新** | `AccountingCache.afterCrudSuccess`：有回傳整列 → **改快取裡那一筆**；改不到 → **整包清掉**。移除 LINE 綁定會從列表刪掉那一列，不把「已停用」再塞回去 |
| **清除** | `AccountingCache.clear(session)`（只清這個使用者的主檔包） |

**bootstrap 內容（現行）**：權限 ≥2 才有廠商（含 `line_ids_accounting`／`line_ids_official`）。權限 ≥3 才另外附合成的 LINE 綁定列表。收款帳戶、費用分類、訂編案號對照**固定空陣列**（後端不讀那些廢棄分頁）。另有列舉與這個人的權限摘要。快取 key：`tanxin_accounting_bootstrap_v6`。

**同一個瀏覽器的其他登入**：`peekVendors` 會掃這個網站底下**任何一份**主檔包（含已超過 3 天的），給下拉先用。名冊是全公司共用的，不是另一個人的私帳；但可能是舊帳號或舊銀行帳號。見 §7。

**戰情側欄（權限 ≥ 4）載入閉環**：載入中／真的空／讀失敗要分開。讀失敗時不可用空名單去算「今日已打卡尚未回報」（以免假紅字）。款項待辦同理。

**專案看板載入閉環**：載入中／真的沒有你負責的案子／讀失敗要分開。讀失敗不可顯示成「沒有符合權限的專案」。有舊快取就留著，並標更新失敗。身分還沒就緒時不可當成沒案子。

**共用工具**：`shared/js/utils.js` — `saveCache(key, data, days)` 預設 **7 天**；會計相關 key 已明確傳 `3`。

## 6. 失效與讀取流程摘要

### 6.1 會計主檔（bootstrap）

人怎麼走：

1. 打開會計選單。權限至少 2，而且這台還沒有廠商名冊時，才向後端要一整包。
2. 這台已有未過期、而且裡面有廠商的名冊 → 直接用，不再向後端要。
3. 沒有、或已超過 3 天、或人按強制重載 → 向後端要。後端若 6 小時內已有同一階的暫存就直接給；否則掃廠商表再存起來。
4. 子頁（廠商名冊、記帳）先看自己這包；沒有就先等外框，或暫時用這台瀏覽器裡任一份名冊把畫面畫出來。
5. 自己改廠商成功 → 只改這台裡的那一筆，並請後端清掉共用暫存。別台要等這包過期或有人強制重載。

```
打開會計
  → 這台已有廠商名冊且未過 3 天？
      ├─ 有 → 直接顯示（不再背景更新）
      └─ 沒有 → 向後端要一整包
            ├─ 後端 6 小時內有同一階暫存 → 馬上給
            └─ 沒有 → 掃廠商表 → 存進後端暫存與這台瀏覽器
  → 自己改廠商成功 → 只改這台那一筆，並清掉後端暫存
```

| 白話（圖上寫的） | 程式對照 |
|------------------|----------|
| 打開會計 | `modules/accounting/index.html`；權限 ≥2 且 `needsStaffBootstrap` 才 `AccountingCache.load(..., true)` |
| 這台已有廠商名冊且未過 3 天 | `AccountingCache.load`：廠商筆數 &gt; 0 就回快取，不呼叫背景更新 |
| 向後端要一整包 | `AccountingApi.bootstrap` → `action=accounting_bootstrap`；單次最多 120 秒，最多再試 3 次 |
| 後端 6 小時內有同一階暫存 | `readBootstrapCache_`／`writeBootstrapCache_`（`MasterBootstrap.js`） |
| 掃廠商表 | `listEntityRowsForBootstrap_('vendor')`；權限 ≥3 再 `synthesizeAllVendorLineBindings_`（廠商表再掃一次） |
| 存進這台瀏覽器 | `AccountingCache` 的 `sessionStorage` 與 `localStorage`，key `tanxin_accounting_bootstrap_v6:{userId}` |
| 自己改廠商成功 | `AccountingCache.afterCrudSuccess`；後端 `afterSheetCrudMutate_` → `invalidateAccountingBootstrapCache_` |
| 廠商名冊有舊名單就先畫 | `vendors.html` 的 `loadVendorList`；自己與瀏覽器都沒有廠商才強制重抓 |
| 讀失敗可再載、舊名單留下 | 同頁「重新載入最新」；失敗且畫面上已有名單則留著並說明失敗 |
| 真的沒有廠商 | 同頁文案「目前沒有廠商」；篩選沒命中才是「沒有符合篩選的廠商」 |
| 新增／修改後就地改那一筆 | `patchMaster`／`refreshVendors(true)` |

追加減與收款的案件列表不在主檔包裡，規則維持：載入中、真的沒有、讀失敗要分開；待辦失敗不可變成空白。

| 白話（圖上寫的） | 程式對照 |
|------------------|----------|
| 追加減與收款管理案件列表 | `modules/accounting/designer-customer-finance.html` 的 `loadOverview` |
| 待辦讀失敗不空白 | 同頁 `loadTodos`；失敗保留 `lastTodosItems` 或顯示再試 |

**實作責任**

| 層 | 誰負責 |
|----|--------|
| 前端 | 新增／修改主檔成功 → `AccountingCache.afterCrudSuccess`（先改那一筆，改不到才整包清） |
| 前端 | 建立廠商資料夾、上傳廠商照片成功 → 同樣走 afterCrudSuccess／欄位 patch |

### 6.1.1 CRUD → 快取更新對照（定案）

| entity／動作 | 前端主檔快取怎麼處理 | 後端暫存 | 下次讀取 |
|--------------|----------------------|----------|----------|
| `vendor` | **優先改那一筆**；改不到才整包清 | 兩把主檔暫存都清 | 這台有廠商就直接用，不再背景更新 |
| `vendor_line_binding` | 停用時從列表刪掉；其餘改那一筆 | 同上 | 同上。名冊畫面只看這份列表，不看廠商列上的 LINE 原文 |
| `payee`／`category`／`order_project_map` | 前端還留著可改那一筆的鑰匙 | 寫入仍會清暫存；訂編另清單次記憶體 | **後端已不再讀這些分頁**，主檔包固定空陣列。不要再當現行主檔 |
| 建立廠商資料夾／上傳廠商照片 | 改廠商資料夾欄位（或走 afterCrudSuccess） | 相關寫入會清暫存 | 同上 |
| 帳本狀態／廠商付款／毛利等交易 | **不動**主檔包 | 依模組（見 §3） | 各頁即時查 |
| Checkin 員工／案場 CRUD | HUB 員工／案場快取（HUB 端） | Checkin 暫存 | HUB 背景更新；會計表單可補抓 |

**原則**：會寫進主檔包的資料，存檔成功後**優先只改那一筆**；只有改不到時才整包清掉。  
**限制**：只保證「**自己這台瀏覽器、自己改過的**」是新的。別台在廠商還在快取裡時，不會 24 小時背景更新，最快要等 **3 天**或強制重載。

### 6.2 訂編案號對照（已停用）

主檔包裡的訂編對照固定是空的，不再讀那張分頁。舊程式若還呼叫寫入，只會清掉「這一次執行裡」的索引記憶體，**不會**更新瀏覽器上的主檔包。記帳用的案場改走案場清單，不走訂編對照。

### 6.4 風險與等待

| 風險 | 人會碰到什麼 | 現在怎麼等 |
|------|----------------|------------|
| 別台改了廠商 | 這台最多 3 天仍是舊銀行帳號、舊合作狀態 | 有廠商就不再背景更新；可進名冊按重新載入 |
| 權限 2 與 3 共用後端暫存 | 主管可能看到「尚無綁定」 | 這包會在瀏覽器再留 3 天。見 §7，尚未分開 |
| 冷啟動掃整張廠商表 | 第一次開會計可能要等；權限 ≥3 同一張表掃兩次 | 畫面有「讀取中」，單次最多 120 秒，失敗再試最多 3 次 |
| 後端暫存塞不下 | 廠商很多時，6 小時暫存可能存失敗（單把約 100KB），每次都改掃表 | 失敗被吃掉，請求仍當成功回傳剛掃到的資料；瀏覽器仍可存 3 天 |
| 這台有另一份舊名冊 | 自己這包是空的時，可能先畫過期或別次登入留下的廠商 | 向後端失敗就留著，文案像「仍顯示先前內容」。見 §7 |

## 7. 已知限制與已知問題

1. **後端暫存最長 6 小時**，3 天那份只能放瀏覽器。
2. **單把暫存約 100KB**。主檔包太大時 `writeBootstrapCache_` 失敗會被吃掉，等於沒有後端暫存，每次都掃表。是否已超過，本輪沒有量實際名冊，標為不明。
3. **權限 2 與權限 3 不該共用同一把後端暫存**（已知問題，尚未修）。權限 3 若在 6 小時內接到權限 2 先放進去的那包，回傳仍是成功，但沒有 LINE 綁定列表。廠商名冊只看這份列表，會寫「尚無綁定」。瀏覽器再存 3 天且不再背景更新。修法：至少把「有沒有綁定列表」拆成不同的暫存鑰匙；名冊在列表是空的、但廠商列上有 LINE 時，不要顯示成尚無綁定。
4. **同一台瀏覽器的 `peekVendors` 不看是誰的快取、過期也拿**（已知問題）。名冊頁或待匯款在自己這包是空的時會先畫這份；若接著向後端失敗，畫面上的舊名單會留著，文案像「仍顯示先前內容」。銀行帳號可能是舊的。修法：只讀這個使用者、未過期的那包；過期或別人的鑰匙不要拿來當成功名單。
5. **員工權限**變更後，`acct_emp_*` 最慢 6 小時才過期。
6. 有廠商就不再 24 小時背景更新，與檔頭舊註解不一致。這是現行行為，不是「已有 24 小時更新」。可改進：超過 24 小時仍在背景重抓，失敗不要蓋掉畫面上的名單。
