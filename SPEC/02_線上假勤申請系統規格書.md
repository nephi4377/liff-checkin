# 線上假勤申請系統 - 前端規格 (v3.0)

> 最後對照程式：2026-11-11（Asia/Taipei）｜規格管理 F1-b  
> 程式為準：`modules/attendance/leave_request.html`、`approval_dashboard.html`；後端 `Backend_GAS/CheckinSystem/Logic_Leave.js`

## 1. 一句話

員工在 LINE 主控台申請請假／加班、補證明、查進度；主管核准後寫進班表，並連動年度統計與薪資相關標籤。

## 2. 人怎麼走

1. 開「線上假勤申請」→ 選請假或加班、時段、事由（必要時附圖）。
2. 送出後進待審；**病假**可先成「已報備」，之後再補證明。
3. 「我的假單」看狀態；待審可撤回；已准且未過期可申請銷假。
4. 權限足夠者用「假單管理」或「假勤審核儀表板」批准／駁回；更高權限可標特別假／颱風日。
5. 核准後班表加上假別／加班時段，員工收到通知。
6. 出勤／薪資頁可對到假勤；生理假等規則見 `22_假勤與出勤獎金規則*`。

## 3. 頁面與 API 對照

| 白話 | 程式對照 |
|------|----------|
| 申請頁 | `modules/attendance/leave_request.html`（路由約 `#/leave-request`） |
| 審核儀表板 | `modules/attendance/approval_dashboard.html` |
| 送出／補件 | POST `submit_leave_request`（補件帶原單時間戳等欄位；**不是**舊稿 `action: 'supplement'`） |
| 主管改單 | `update_leave_request` |
| 我的假單 | GET `get_my_leave_requests` |
| 待審列表 | GET `get_pending_requests` |
| 批准／駁回 | `handle_approval` |
| 撤回 | `cancel_leave` |
| 銷假申請 | `request_leave_cancellation` |
| 特別假／颱風 | `mark_company_leave_day`／`mark_typhoon_day` |
| 年度統計 | `leave_year_stats`（`leave_year_stats_*.js`） |

## 4. 狀態與證明（現行）

- **病假**：可先「已報備」，補證明後再進入待審流程（以後端為準）。
- **公假**：頁面若寫「可先報備再補證明」，須與後端狀態機對齊；**目前易不一致**（見風險）。勿再寫已廢棄的「待補件」＋`supplement` 當唯一路徑。
- 假別色彩：`APP_SETTINGS.LEAVE_TYPE_COLORS`（事假／病假／特休／補休等）。
- 生理假、特別假／颱風與獎金規則：對齊 `SPEC/22_假勤與出勤獎金規則計劃.md`（獎金切換屬政策，預設可能仍 legacy）。

## 5. 資料來源

1. 優先父層 SPA：`window.parent.spaAllEmployees`  
2. 否則 GAS：`get_employees`  
3. 身分：LIFF 內嵌；本地測試可跳過（僅開發）

## 6. 風險與等待

| 維度 | 摘要 |
|------|------|
| 交叉 | 公假文案「先報備」與後端「僅病假已報備」可能不符；銷假清班表若班表字串含時段，只比假別名可能清不掉；`cancel_leave` 若不核對申請人／狀態有誤消風險 |
| 延時 | **中～高**：假單列表／審核常整表讀「排班歷史」；有證明需上傳 |
| 可改進 | 前後端統一報備／補件狀態機；銷假清班表支援時段格式與跨日；審核請求避免純 `no-cors` 樂觀成功 |

## 7. 已知問題（勿寫成正確行為）

- 銷假核准清班表、撤回 API 權限邊界：見 `TOS/規格巡檢回報.md` 本輪 Bug。
