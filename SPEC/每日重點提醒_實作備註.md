# 每日重點提醒 — 實作備註

主計劃見 [`每日重點提醒_SPEC.md`](每日重點提醒_SPEC.md)。此檔才記程式／接線，避免計劃一開頭被技術清單擋住。

---

## 程式對照（對齊主計劃流程圖）

| 白話（主計劃） | 程式對照 |
| --- | --- |
| 排進 iCloud 公開訂閱日曆 | 與添心小幫手同一訂閱網址（設定裡的 iCloud 行事曆；`webcal://` → `https://` 後抓 ICS） |
| 早訊讀今天／明天行程 | Hermes cron：下載 ICS、解析 VEVENT（含 RRULE 盡力展開）；對齊小幫手 `fetchIcloudEvents` 精神，但早訊要**同時**今天＋明天 |
| 送施工回報 | 既有 LIFF 施工回報 → ProjectLog |
| 早訊讀工地近況 | project-console `get_daily_reports`（`startDate`／`endDate`）；可選 `get_site_ai_analysis` |
| 早上收到短訊 | Hermes cron `deliver: telegram,email`（可再加 `line`） |
| 整理失敗可再要 | 人對 Hermes 說「再給今日重點」；或 `hermes cron run <job>` |
| 每日回報頁看細節 | CODING `#/` 每日回報（`daily_report.html`）既有頁 |
| 隨口「提醒：…」（階段 2） | Hermes 對話寫入可查清單（待定：Sheet／記憶檔）；**不要**掃一般 LINE 群歷史 |

**日曆主來源＝iCloud 公開 ICS，不是 Google Calendar OAuth。**  
小幫手參考：`添心生產力助手/client/src/apiBridge.js`（`fetchIcloudEvents`／`syncAllIcloudReminders`）。訂閱網址只存在本機設定／config，**勿**把完整 URL 寫進本 SPEC。

## 可貼給 Hermes 的設定稿（階段 1）

先換成你的值，再**整段貼進 Hermes 對話**：

1. `YOUR_ICLOUD_ICS_HTTPS_URL`＝添心小幫手設定裡的 iCloud 訂閱網址，把開頭 `webcal://` 改成 `https://`，並去掉 `?` 後面參數  
2. `YOUR_PROJECT_CONSOLE_EXEC_URL`＝專案後端 Web App `/exec`（與每日回報頁同一條）  
3. Email 未設好則投遞改 `telegram`，或先 `hermes gateway setup` 選 Email

```text
請建立一個每天早上 8:00（Asia/Taipei）執行的排程，名稱：daily-tianxin-brief。
投遞：telegram,email（若 email 未設定則只用 telegram，並告訴我）。

每次執行時產出「今日重點」短訊（繁體中文），規則如下：

【資料來源】
1. 行事曆（主來源＝添心小幫手同一份 iCloud 公開訂閱，不是 Google 日曆）：
   - 用 HTTP GET 下載 ICS：YOUR_ICLOUD_ICS_HTTPS_URL
   - 解析 VEVENT；列出「今天」與「明天」（Asia/Taipei）的行程（時間、標題、地點）
   - 有 RRULE 的重複行程要展開到這兩天；整天行程標「整天」
   - 下載或解析失敗 → 狀態註明「行事曆未連上」，不要假裝有行程
2. 工地：HTTP GET（日期換成執行當下的昨天與今天，YYYY-MM-DD）：
   YOUR_PROJECT_CONSOLE_EXEC_URL?page=get_daily_reports&startDate=昨天&endDate=今天
   從 JSON 的 data 整理需盯重點（案號、AI_Summary／內容摘要、AI_Signal 紅黃燈優先、回報人）。最多 8 條。
   連線失敗 → 狀態註明「工地資料未連上」。

【輸出格式・不可改標題】
今日重點 · M/D（星期）
狀態：已整理｜已整理（某來源未連上）｜整理失敗

■ 今天必做
・…

■ 明天預告
・…

■ 工地相關
・…

■ 其他
・…

規則：每條一行一句話；無則寫「無」或「近兩日尚無新回報」；不要 JSON、不要整表、不要灌水。
若日曆與工地都失敗：只輸出整理失敗短訊，並提示我說「再給今日重點」可重試。

建好後立刻手動跑一次給我看樣本，並回報 job 名稱與下次執行時間。
```

### CLI 備案（對話建立失敗時）

```bash
hermes cron create "0 8 * * *" "（貼上與上方相同的產出規則全文，並填好兩個 URL）" --name "daily-tianxin-brief" --deliver telegram,email
hermes cron run daily-tianxin-brief
```

Email 環境變數（`~/.hermes/.env`）記得含 `EMAIL_HOME_ADDRESS=你的信箱`。

## 接線注意

| 項 | 說明 |
| --- | --- |
| iCloud ICS | `webcal://` → `https://`；公開訂閱、免 OAuth；與小幫手共用同一 URL |
| 施工資料 | 已有 `get_daily_reports`；不必新建回報管道 |
| LINE 一般對話 | Messaging API **不能**讀使用者私人聊天／Keep；階段 3 明確不做 |
| LINE 案號群 | 已進 ProjectLog 者，會被「工地相關」覆蓋，無需另掃 |
| `AI_ConversationLog` | 有寫入、無對外查詢；階段 2 若要用須另開查詢，非早訊必要 |
| Email | Hermes `EMAIL_*`＋`EMAIL_HOME_ADDRESS`；cron `--deliver telegram,email` |

## 驗收（階段 1）

1. 到點（或手動跑一次）收到早訊，四段標題齊全。  
2. 「今天必做／明天預告」與 iCloud 訂閱日曆一致（抽 1～2 筆對稿）。  
3. 當日有施工回報時，「工地相關」有案名級摘要。  
4. 日曆與工地都空時，四段仍在，內容為「無／尚無」。  
5. 故意斷一個來源時，狀態行說明「某來源未連上」，其餘仍出。  
6. Telegram 與 Email（若都有設定）都能收到同一則重點。
