# 專有名詞白話對照（給對話與文件用）

> **用途**：助理或文件必須用到技術詞時，優先用這裡的說法；表內沒有的詞，**第一次出現請在括號內加一句白話**，並可補一行到本表。

| 專有名詞 | 白話意思（可照抄給使用者看） |
|----------|------------------------------|
| **API** | 程式跟遠端服務「要資料或下指令」的約定接口（像點餐單上的編號）。 |
| **CDN** | 放在網路上的現成套件倉庫，開網頁時會去下載圖示、樣式等（需連網）。 |
| **Commit** | 把這一版變更存進版本紀錄，像存檔＋寫一句備註。 |
| **PR（Pull Request）** | 請別人審核「要不要合併這一版程式」的申請單。 |
| **SPEC／規格** | 事先寫好的「應該長怎樣、怎麼用」說明書。 |
| **Repository／Repo** | 整包專案程式與紀錄放在一起的資料夾（通常含 Git）。 |
| **瀏覽器** | Chrome、Edge、Safari 等用來開網頁的程式。 |
| **iframe** | 網頁裡嵌的另一個小網頁畫面（像子視窗）。 |
| **路由（Route）** | 網址 `#/xxx` 對應要開哪一頁的對照表。 |
| **OpenCV** | 做影像辨識、校正等運算的程式庫（常需連網下載）。 |
| **透視校正** | 把斜著拍的矩形（例如圖紙）拉成「正正的長方形」的運算。 |
| **Bounding box／外接框** | 剛好包住選取範圍的「不旋轉的長方形邊界」。 |
| **案場** | 這一個工地／這一戶裝修專案的現場與相關資料（地址、進場方式等）。 |
| **專案起始日** | 案場表上手填或排程帶入的開工欄位；毛利工期「開始日」優先用這個。 |
| **開工日（推算）** | 若「專案起始日」空白，改看保護／木作／油漆／系統工程第一則已發布施工紀錄的日期。 |
| **完工照資料夾** | Dropbox 專案夾底下、名稱含「完工照」且不含「美照」的資料夾（例：`1160722完工照`）；放完工照片與實拍影片。 |
| **串流留言／留言串** | 針對同一則進度或同一則留言，可以一層層回下去，像社群軟體的討論串。 |
| **客戶進度頁** | 給屋主看的專用畫面，通常只能看自己家、且多半是已公開的進度。 |
| **語音留言** | 錄一段聲音上傳給對方聽（和「語音轉成文字」不同；多數情境可先不做）。 |
| **綁定（客戶與案號）** | 把「這一戶案號」跟「這一位客人的 LINE」連起來；連好後客人才看得到自己的案。**2026-08-14 總監改口**：客人自助＝填案號＋地址＋（業主姓名或手機末四碼）**對上即綁**，不強制人工審；**後備**＝內部代綁。 |
| **客人申請綁定頁** | 給屋主自己填案號、地址、業主姓名或手機末四碼的畫面。對上就生效；案場沒填業主資料時對不上，請設計師代綁。 |
| **業主姓名／業主手機** | 案場資料上的屋主姓名與手機，**選填、不強制**。給設計師建檔、主控台查案、客人自助綁定核對用。**不出現在進場資訊，也不出現在 LINE 查案回覆**。 |
| **客戶綁定審核頁** | 內部看「誰申請綁案還沒過」的佇列頁；可核准或駁回。**已拍板**：獨立小頁，從會計選單（HUB）一卡進入；審核權限 **≥4**。單案「客戶綁定」分頁只作代綁後備。 |
| **裝修案會員專屬 Rich Menu** | 客人至少**審核通過**綁過一案之後，LINE 聊天室下方換成的會員大圖選單（六格：**收款確認｜我的案場｜綁定新專案｜了解添心｜常見問題｜Facebook**）。**不掛**施工進度、簽約／追加減核對。 |
| **簽約單／追加減核對** | 給客人看「簽約後變更單」（現場常當合約附件）並做品項核對驗收、問題改進、備註的專區；**不**放在收款確認頁。客人可見「洽談中」內容；須整單簽＋一鍵勾選確認後，再經公司落實才算確定項目。 |
| **洽談中（追加減核對）** | 變更還在討論、尚未定案；客人可看明細，但畫面要標「尚未定案」，不能當成已報價定案。 |
| **客戶已確認（追加減核對）** | 客人已整單簽名並一鍵勾選完成；系統已記下確認時間／簽名／勾選；等公司落實入帳。 |
| **已確定／已核准入帳（追加減）** | 公司依客戶確認結果正式入系統；才計入有效合約（與「公司確認」同一語意）。 |
| **預設 Rich Menu（未綁定）** | 剛加官方 LINE、還沒有任何「已通過」綁定時的下方選單（四格：**申請綁定專案｜了解添心｜常見問題｜Facebook**）。待審／已駁回仍算未綁定。Facebook **外開**，不在 LINE 內嵌頁開。 |
| **提出異議（追加減核對）** | 客人在「客戶已確認」後反悔、要求重談；按下去該單回到洽談中並留痕。公司已確定入帳後，客人不可自助異議。 |
| **ClientPortalAccess（客人與案號對照表）** | 試算表裡紀錄「哪個 LINE 能看哪個案號」的分頁；可多案、可解除。現行狀態只有已通過／已解除；**需加**待審核／已駁回。 |
| **待審核（綁定）** | 客人已送出綁案申請，內部還沒核准；此時不能看該案、也不換會員選單。 |
| **已通過（綁定）** | 審核核准或內部代綁完成；客人可看該案；若是該 LINE 第一筆已通過則換會員選單。 |
| **已駁回（綁定）** | 審核不通過；維持預設選單（若無其他已通過）；客人可再申請。 |
| **客戶進度頁（唯讀）** | 給屋主只看施工紀錄進度用的畫面，不能改資料、不能留言（除非日後另開功能）。 |
| **空間標籤** | 選材／現場用來標「這批材料用在哪個空間」的標籤，可複選（如客餐廳、主臥、次臥、全室、玄關、衛浴、陽台）；不是品名也不是工種。 |
| **部位／材料標籤** | 選材用來標「這是哪種部位或材料」的標籤，可複選（如地板、磁磚、櫃體、門板、中島／枱面等）；品牌型號請寫補充說明，不是獨立欄位。 |
| **選材快層** | 客人看選材圖時用的暫時圖庫（約 30 天過期）；過期先對清單，一樣就不搬。長期仍靠雲端硬碟與 Dropbox。 |
| **選材每日比對** | 系統一天一次、只對未結案：核對選材夾裡有沒有還沒進清單的檔；剛丟檔不想等，可按「現在補一次」。 |
| **Rich Menu（大圖選單）** | LINE 聊天室下面那一排大圖按鈕；可以設成按一下就直接開網頁或開 LIFF。 |
| **#測試選單** | 有權限的人在官方帳號私訊打 `#測試選單 員工`／`四格`／`六格`，只換自己聊天室下方的大圖，用來測客人畫面；測完換回員工。不會改別人、也不會變成全公司預設。 |
| **全員出勤燈號看板** | 主控台看全員今天排班與打卡燈號的畫面；**權限 ≥ 3** 可見。 |
| **排班制** | 員工的班表採每月排定、休假不固定的制度；需到排班系統設定每月哪幾天休。 |
| **標準制** | 員工的班表固定（例如週日休加國定假日），平常不需另排；僅在請假或加班時才需要登記。 |
| **待審核（假勤）** | 有人已送出請假或加班申請，但還沒被主管核准的狀態。 |
| **LIFF** | 在 LINE 裡面開你的網頁的一種方式，網頁程式可以取得使用者的 LINE id（用來對應「哪一位客戶」）。 |
| **客戶頁門牌** | LINE 開網頁時最上面那一行名字。申請綁定、收款、我的案場共用，**定稿＝我的裝修案**。畫面裡的大標題仍可寫「申請綁定專案」。不拆成兩扇門。**2026-08-15**：同一扇門、三把 LINE 鑰匙——收款鍵只看收款；我的案場鍵只看選材；綁定鍵只綁案。頁內不再重複放這三個按鈕。 |
| **明細_X00／明細_X00全部** | 案件毛利裡依案號百位合併的明細分頁（例如 726 進「明細_700全部」）；列上有案號欄。 |
| **開詳情重算** | 點開某一案毛利詳情時，系統依該案目前明細重新加總收／支／毛利，畫面上方摘要與總覽列一併更新。 |
| **已實現／未實現** | 已實現＝錢已發生、直接記收支；未實現＝先請款審核、匯款結案後才寫收支。 |
| **扣匯費（待匯款勾選）** | 有勾＝銀行實匯少 $30（廠商少收），入帳／案場分攤不加匯費；沒勾＝公司幫出 $30，入帳與「金額最大那案」毛利直接加進去。 |
| **預設扣匯費（廠商名冊）** | 在廠商名冊設好這家廠商平常要不要扣匯費；之後新建請款／待匯款會自動帶這個設定，單筆仍可在待匯款改。 |
| **款項進度** | 看自己（或代查某廠）請款走到哪：待審、待匯、已匯、退回。 |
| **廠商待匯款** | 財務把已核准（或直接新增）的請款匯出去的那一頁；這裡才寫收支。讀不到時要說失敗，不能裝成「目前沒有待匯款項目」。 |
| **請款必連五件事** | 一筆請款必須能連到：明細收支、案件毛利、LINE 通知、檔案雲端、綁定廠商；缺一則流程不完整。 |
| **請款 LINE 通知** | 只在「標記已匯款」時推播廠商；不因送審／退回另推，以免超過額度。 |
| **廠商別名／發票公司名** | 名冊上「日常稱呼」以外、單據上會出現的公司名。辨識讀到別名就對到這家廠商。 |
| **出帳末五碼** | （已停用）舊版匯款通知會寫公司中信帳號末五碼；因常改私人帳戶轉帳易誤導，**現行文案已不寫**。 |
| **電話純文字／補 0** | 電話在試算表要用文字格式存，開頭的 0 才不會消失；手機等不是 7 碼市話的，系統會自動補上開頭的 0。 |
| **Token／權杖** | 一串密碼字元，讓程式確認「這個連結或這支手機可以讀哪一些資料」，不必把整本帳密交出來。 |
| **水電明細表** | 開關、插座、迴路、專用回路等「一覽表」，審水電圖時要拿來和平面／立面互相對照的那張（或那份）。 |
| **+100（圖面標註）** | 常見的「加厚／完成面」尺寸寫法之一，實際代表幾公分要看圖例與比例；重點是壁板／造型要有**可施工的厚度標示**。 |
| **GAS（Google Apps Script）** | 在 Google 雲端跑、常接表單／試算表與觸發排程的小程式；本專案後端 WebApp 在這裡。 |
| **UploadQueue** | 試算表上「待背景處理回報」的佇列列；狀態會從待搬運→待處理→（失敗則待重試）→已完成；滿 5 次失敗會寄信並標最終失敗。 |
| **報價審核器** | 內部用的「工項驗收」網頁（`BudgetAuditor_Standalone_V2`）：連 Firebase 打勾進度、可選顯示單筆金額。 |
| **畫布邊長（Layout Planner）** | 平面可編輯區域的邊長（此工具裡與圖上 cm 1:1）；數字愈大工作區愈大、可捲動範圍愈大。 |
| **報價合併列（LayoutPlanner）** | 天花／地板等同條件且圖上**夠近**可併一列；**櫃體／標註**改為每個各一列，副屬性（如二抽）列在該櫃下方。 |
| **分類圖層（LayoutPlanner）** | 依 Sheet 群組（水電、櫃體、木作…）勾選顯示／隱藏畫布上的元件與標註。 |
| **快速報價（清單式）** | 不畫平面圖，用「空間＋坪數＋勾選工項」組出估價明細；適合現場初估，技術規格見 `SPEC/14_室內裝修快速報價系統規格書.md`。 |
| **gviz（網路試算表讀法）** | 試算表在「可匿名讀取」的狀態下，可用網址參數把指定範圍**拉成表格式 JSON**；可 **A 欄＝內用 `id`、B 欄＝單價**，或依**分頁＋A 欄品項**對 **B 單位、C 單價** 寫入品項。 |
| **OCR（帳單辨識）** | 用 AI 讀發票／請款單照片上的廠商、金額等文字。 |
| **本公司抬頭** | 單據上的「添心設計／添鑫創意」等買方名稱，是客戶標示我們，不是請款廠商；辨識與審核會排除。 |
| **廠商請款慣例** | 名冊上這家廠商平常怎麼請款的設定（別名、預設扣匯費等）；審核／新建請款可依此帶入。 |
| **通用辨識指令** | 全公司一份、給請款 AI 看的補充說明（例如怎麼讀對帳單）。 |
| **專用辨識說明** | 某一家廠商專用的辨識說明；單據樣式特別時寫在名冊。 |
| **二階段辨識** | 先只用通用辨識；結果不夠好且已知道廠商時，再用該廠專用說明自動再辨一次。 |
| **辨識核對卡** | 群裡先秀出讀到的請款內容，按「確認送審」才真的送主管審。 |
| **Firebase Realtime Database** | Google 的即時資料庫（像一棵 JSON 樹）；本頁快速報價設定可存到指定路徑，多裝置共用。 |
| **客戶可見備註** | 管理員在品項上填的說明，**產生報價小表時預設一併顯示**在品名旁邊，方便符合慣用報價格式。 |
| **定量（菜單／估價）** | 數量由菜單**寫死**一個值（幾尺、幾坪、幾式），不隨空間邊長比例重算。 |
| **變量（菜單／估價）** | 數量由**空間的長邊或短邊**、坪等**先算**再依方案乘上**比例%**；寫在方案 JSON 的 `type` 與參數裡。 |
| **員工預覽（staff_preview）** | 員工用參數打開「客戶收款頁」，畫面跟客戶一樣、可切全部案號，但只能看不能代按確認／簽名。開發測試略過登入時也列出全部案件。網址用 `#staff_preview=1`（不要用問號參數，否則 LINE 會擋）。 |
| **待付款請款** | 錢還沒付給廠商／員工：上傳發票、填金額、送主管審，通過後才匯款。 |
| **單據與存檔** | 處理「這張檔是什麼、歸哪家」：LINE 傳來的圖在這裡分類；報價／合約也可在同一頁上傳進廠商資料夾。不是請款。 |
| **單據附件索引** | 記帳／請款上傳的照片與檔案連結清單；財務主要用案號或廠商名查找。 |
| **每日重點提醒／今日重點** | 早上自動送來的短訊：今天必做、明天預告、工地該盯的事；日曆來源＝添心小幫手同一份 iCloud 公開訂閱。見 `每日重點提醒_SPEC.md`。 |
| **出勤獎金（試算表欄位常叫全勤）** | 員工主檔設定的「全勤才發／依規則扣」的加項上限；畫面統一叫出勤獎金。規則見 `SPEC/22_假勤與出勤獎金規則計劃.md`。 |
| **颱風假** | 天然災害停班或符合勞動部要點而未出勤的日子；不當缺勤、不扣出勤獎金；本薪建議照給。老闆可於假勤審核頁快捷標註。 |
| **特別假（公司假）** | 老闆標的全員特別假；可選不扣薪，或扣薪並選出勤獎金「整筆不發／照舊」。見 `SPEC/22`。 |
| **生理假** | 性平法規定的生理假；不得因此扣出勤獎金；請假時須與「病假」分開選，系統才分得清。 |
| **含稅（請款勾選）** | 標這筆是含稅價；**不會**自動改金額。廠商價本來就含稅時勾這個。 |
| **未稅加 5%（請款勾選）** | 把目前金額加 5% 營業稅（×1.05），並自動標成含稅。廠商價是未稅時勾這個。 |
| **在職窗（薪資／超休）** | 計薪期裡「到職日～離職日」重疊的那段日子；本薪折算與可排休額度只算這段。 |
| **缺勤** | 應出勤卻沒請假、沒來；可扣當日比例本薪；建議出勤獎金整筆不發。 |
| **主控台身分** | 從 LINE 主控台點進會計時，這一分頁已記住的「你是誰」；會計沿用，不必再刷通行證。 |
| **款項待辦** | 主控台左側給主管看的「還有哪些廠商請款等審、等匯」。連線失敗時應說失敗並可再試，不能顯示成「目前沒有待辦」。 |
| **失敗≠空** | 列表第一次沒讀到，不能顯示成「目前沒有資料」；要說載入失敗、可再試，有舊資料就先留著。廠商名冊、款項待辦、薪資列表、追加減與收款案件列表都適用。 |
| **專案看板** | 主控台上方分頁，列出你負責的案子卡片。連線失敗時應說失敗並可再試，不能顯示成「沒有案子」。 |
| **錯誤回報開關** | 控制失敗時要不要自動寫雲端紀錄／寄信。關掉後畫面仍可「複製錯誤」。使用者說關掉時：會計 GAS 執行 `setAccountingErrorReportOnce(false)`。見 `SPEC/19`、accounting-gas `LINE_OA_SPEC` §5.1。 |
| **複製給 Cursor** | 把這次錯誤整理成一段文字，複製後貼到 Cursor 對話給助理看。網頁沒辦法自己送到 Cursor。 |

**維護**：新增詞條時保持「一行白話」即可，不必寫論文。
