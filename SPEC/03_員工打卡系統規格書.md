# 員工打卡系統 - 穩定性與同步技術規格 (v2.0)

## 1. 核心定位
本系統 (`checkin.html`) 為全專案對穩定性要求最高的「承重牆」模組，具備在地圖環境不穩下的極佳容錯與數據完整性。

## 2. 關鍵技術實作

### 2.1 Single Sink 調度引擎 (AppAPI.dispatch)
- **併發防護**: 利用 `isDispatching` 旗標鎖定，確保在回傳前不會重複發起請求。
- **來源識別**: 自動判定 `source` 為 `hub` (主控台), `assistant` (小助手) 或 `richmenu` (LINE 菜單)。

### 2.2 高階斷網容錯 (Resilience)
- **寬限期重試**: 偵測到實體斷網時，進入 **5 秒寬限期**，顯示倒數 UI 並等待自動恢復。
- **三段階重試 (Retry Policy)**: 針對 5xx 錯誤或 API 逾時自動執行 3 次重試，每次遞增等待時間。

### 2.3 離線紀錄隊列 (Offline Queue)
- **持久化儲存**: 失敗紀錄暫存於 `checkin_offline_queue` (localStorage)。
- **自動同步**: 系統啟動 (liff.init) 後自動觸發 `syncAll()`，將隊列紀錄依序補傳至 GAS。
- **去重機制**: 每一筆紀錄具備唯一的 `pageInstance` ID，防止補傳時造成重複打卡。

### 2.4 GPS 擷取協議 (AppGeo)
- **高精確模式**: 強制開啟 `enableHighAccuracy`。
- **逾時控制**: 鎖定 12,000ms 擷取上限，防止 GPS 模組喚醒失敗導致頁面卡死。
- **自動重試**: 點「立即打卡」時最多再試 3 次定位。
- **逾時後本頁可再打（v26.08.30）**: 定位逾時或訊號弱、**尚未送出打卡**時，恢復「立即打卡」，不必關 LINE。拒絕定位（未開權限）仍須改設定後關閉視窗重開。

| 白話 | 程式對照 |
|------|----------|
| 定位逾時後本頁再打 | `AppCore.restoreReadyToPunch` |
| 拒絕定位才關視窗重開 | `AppCore.endPageSession`（僅 `err.code === 1`） |

### 2.5 案場清單快取（Stale-While-Revalidate，v26.07.22）
- **本機快取**: `checkin_sites_cache`（localStorage，TTL 30 天）。
- **開頁有快取**: 立即使用舊清單啟用打卡；**同時**背景向 `get_all_sites` 靜默更新，成功則覆寫快取並重算 30 天。
- **開頁無快取**: 首次載入最多等待 `SITE_LOAD`（10s）；逾時仍放行打卡，背景每 30s 重試。
- **背景更新失敗或 API 回空陣列**: 不覆寫既有快取，沿用舊清單。
- **案場燈號**: 背景更新中顯示「更新中」，完成後「已同步」。
- **打卡按鈕**: 定位預熱完成須經 `tryEnableCheckinButton`（需案場首次載入完成或已有快取）；無清單且仍在首次載入時，按打卡可再等待一輪。

| 白話 | 程式對照 |
|------|----------|
| 背景更新案場清單 | `AppOffSite.refreshSitesInBackground` |
| 讀寫本機案場快取 | `AppStorage` + `checkin_sites_cache` |
| 開頁首次／背景載入 | `runFirstSiteAttempt`、`startBackgroundSiteSync` |

### 2.6 離場原因選項（v26.07.23）
- **內建於打卡頁** `CONSTANTS.OFF_SITE_REASON_PRESETS`，開頁即用，**不再**呼叫 `get_off_site_reason_presets`。
- 變更選項時須與 `backend/CheckinSystem/Constants.js` 的 `OFF_SITE_REASON_TAGS` 同步；後端送出時仍過濾非法標籤。

### 2.7 兩段式打卡（v26.07.23）
- **第一次**（按「立即打卡」）：定位後**立即**送出打卡（經緯度＋軌跡）；離場時僅標記「離場未填說明」，**不**等離場原因。
- **第二次**（選填）：不在案場時顯示離場說明區；按「送出離場說明」呼叫 `update_off_site_reason`；按「略過」或關閉視窗不影響已寫入的打卡紀錄。
- 後端以 `userId` + `clientTimestamp` 對應更新「打卡紀錄」或「打卡前置記錄」佇列中的 N～P 欄；找不到時排入「離場說明待補」背景重試（最長 5 分鐘）。
- **逾時後重送／離線 queue 補傳**：前端以同一組 `userId` + `clientTimestamp` 再呼叫 `update_off_site_reason` 時，後端應視為**同一筆打卡的補寫**（覆寫 N～P 欄），而非新增第二筆打卡。若第一次其實已成功但客戶端逾時，重送應為冪等更新。本 repo 無 GAS 程式碼；實作細節以 `CheckinSystem` 內 `update_off_site_reason` handler 為準（Cloud Agent 環境若未掛 `Backend_GAS` 則僅能依此規格與 handler 註解驗證）。
- **前端錯誤分流（v26.10.22）**：`success !== true` 或 HTTP 4xx／5xx throw → 維持「送出離場說明」可重試；僅斷網／網路錯誤／通訊逾時才進離線 queue，按鈕顯示「說明已暫存」（非「打卡完成」）。

## 3. 核心設計規範
- **視覺反饋**: 包含 `LINE`, `Network`, `Location` 三大燈號狀態指示。
- **自動關閉**: 打卡**成功**後鎖定按鈕並啟動 45 秒倒數自動關閉 `liff.closeWindow()`。定位逾時／訊號弱尚未送出時，不結束本頁、可再按「立即打卡」。

---
> [!CAUTION]
> 嚴禁修改 `CONSTANTS` 中的逾時設定，這將直接影響案場弱網環境下的打卡成功率。
