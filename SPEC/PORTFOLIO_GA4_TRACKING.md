# 作品集案例頁追蹤檢查規範

本文件供新增或改版 `tanxin.space/portfolio/project-<案號>/` 案例頁時使用。正式案例頁由 WordPress 管理；舊站案例頁的導流另由本儲存庫維護。

## 頁面條件

- WordPress 頁面須為作品集頁面的直接子頁。
- Slug 須為 `project-` 加純數字案號，例如 `project-700`。
- 正式網址須能正常開啟，案號要與頁面內容一致。
- 案例頁追蹤程式應載入並取得正確案號；變更頁面階層或 slug 後務必重新驗證。

## 事件與連結

所有案例事件都應附 `case_id`：

| 事件 | 檢查重點 |
|---|---|
| `case_view` | 開啟案例頁 |
| `case_engaged` | 頁面可見至少 30 秒，且捲動深度達 50% |
| `youtube_click` | YouTube 連結或影片封面點擊、嵌入影片首次播放 |
| `line_click` | LINE 連結點擊 |
| `phone_click` | `tel:` 電話連結點擊 |
| `inquiry_click` | 本站預約／聯絡頁連結點擊 |

CTA 請使用真正的 `<a href>` 連結，並逐一確認連結目的地。若改為 JavaScript 按鈕、新的網址格式或播放器，應同步檢查追蹤程式。特別注意：嵌入頁面或 `iframe[srcdoc]` 內的點擊不會傳到外層頁面；改動影片封面時，要確認內層點擊有被追蹤。

## 發佈前後

1. 核對頁面父層、slug、案號與正式網址。
2. 檢查追蹤腳本是否載入、`case_id` 是否正確。
3. 逐一檢查影片、LINE、電話、預約連結；新形式要先更新追蹤程式。
4. 在 GA4 即時報表或 DebugView 操作頁面，核對事件名稱與 `case_id`。測試時不要真的送出詢問、撥電話或傳送 LINE 訊息。
5. 次日檢查標準報表，標明日期範圍並區分測試流量；事件數不代表實際詢問或成交。

2026-10-05 的案例改版曾把影片封面改成 `iframe[srcdoc]`，導致原本外層 click 監聽無法收到事件；WordPress 追蹤程式已補上內層監聽。之後套用新頁面版型時，請依此清單再驗證一次。
