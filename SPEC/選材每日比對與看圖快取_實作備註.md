# 選材每日比對與看圖快取｜實作備註

主計劃見同資料夾《選材每日比對與看圖快取.md》。總監操作 Firebase（人話、無金鑰）見《選材Firebase操作流程》。這裡才寫模組與接口。  
最後對照程式：2026-11-23（Asia/Taipei）。

## 比對鍵

**入列**

| 鍵 | 用法 |
| --- | --- |
| Dropbox 完整路徑（小寫） | 主鍵：已在表就不新增列 |
| 檔名（小寫） | 輔鍵：同案未作廢已有同檔名也略過 |
| 大小、修改時間 | `source_size`／`source_modified_at` |

**客人快層（指紋）**

`photo_cache_fingerprint` ＝ `檔名小寫|大小|時間`。  
未過期（`photo_cache_expires_at`）且指紋與現況相同 → **不搬**。過期、沒有快層、或指紋不一致才上傳差的。不要整案重傳。

## 快層寫入時機（這一刀）

| 時機 | 做什麼 | 上限 |
| --- | --- | --- |
| 每日比對／「現在補一次」入列**新檔** | 缺硬碟則從已知 Dropbox 路徑補；再把硬碟小圖上傳快層 | 每日每案約 2 張；人手單案約 6 張；仍受時間預算 |
| 設計師頁面上傳照片（已有硬碟） | 順便上傳快層 | 約 12 秒，失敗略過 |
| 客人開頁 | **只讀**已有快層／硬碟；清單請求不上傳、不打 Dropbox | — |
| 客人開頁之後背景 | 最多排隊**一張**且該筆已有硬碟 ID；指紋對上就跳過。失敗仍回成功，畫面不當成連不上 | 約 12 秒 |

## 分段進度（入列）

- Script Properties：`MS_DAILY_SCAN_STATE`
- 單輪約 4 分鐘；下一案前剩不到約 25 秒就停
- `LockService` 避免兩輪重疊

## 觸發器

| 函式（白話） | 何時掛 |
| --- | --- |
| `materialSelectionDailyScan_`（每日未結案比對） | 部署後編輯器下拉跑 `setupMaterialSelectionDailyScanTrigger`（白話：建立每日選材比對；沒有結尾底線）。內部會呼叫同名底線版：清同名舊排程、掛每天約凌晨 4 點。實際每天跑的仍是底線版 `materialSelectionDailyScan_`。**不自動建** |
| `materialSelectionRetentionSweep_`（結案＋2 年清硬碟照） | 既有；仍須手動掛 |

## Firebase 桶路徑（與施工回報分開）

- 施工回報：`reports/{projectId}/{batchId}/…`
- 選材快層：`material-selection/{案號}/{選材id}/{序}_{檔名}`
- **不要**寫進 `reports/`，也勿進施工回報搬運佇列
- 下載網址帶 token（不依賴匿名讀取規則）
- **約 30 天刪檔**：須總監在 Firebase Console → Storage → 生命週期，對前綴 `material-selection/` 設 30 天刪除。Apps Script **無法**代設。

## 設計師儲存（兩段）

1. `margin_material_create` 先 `appendRow`，狀態 `active`。此時客人清單已看得到，照片欄還空。
2. `margin_material_upload_photo` 寫入 Dropbox `選材/` 與硬碟副本，全部成功才寫回該列路徑。單張失敗就整次回失敗，已上傳的檔不會從夾裡刪掉，列上也不記路徑。
3. 前端只有在上傳**回傳失敗**時才呼叫作廢，而且不檢查作廢結果，仍顯示「已取消這筆選材」。上傳丟出例外（含約 60 秒逾時）時不叫作廢，只顯示「儲存失敗」，表單仍開著，再按會再新增一筆。
4. 作廢列沒有路徑。下次「現在補一次」或每日比對用「未作廢列的路徑／檔名」略過；夾裡那些檔會再入列。

編輯說明走 `margin_material_update`，不作廢、不傳圖。作廢走 `margin_material_void`。按鈕有 `disabled`／`voidBusy`，同一次連點不會送兩次；逾時後再按不在此限。

## 現在補一次與每日

- 人手：`margin_material_scan_import`，前端逾時 60 秒；後端 `MS_WEB_SCAN_BUDGET_MS_` 40 秒、最多約 20 筆新檔、快層最多約 6 張。
- 回傳 `success: true` 即使 `failed > 0`。訊息會附「有 N 筆這輪沒寫成」，前端仍用成功色。
- 每日 `materialSelectionDailyScan_`：單案 `success: true` 就清掉該案失敗句（含部分檔沒寫成）。資料夾整夾讀不到才記失敗句。
- 狀態：`margin_material_scan_status` 讀 `MS_DAILY_SCAN_STATE`。

## 客人頁

- 顯示順序：未過期快層 → 硬碟縮圖 →（沒有才）載入中。開頁不 live Dropbox。
- `photos_pending`／`needs_cache_fill`：後者僅在已有硬碟、快層缺了才給背景補一張。
- 清單 `success: false` 與零筆分開。已有卡片時失敗不整頁換成空白。
- 空間、部位、補充說明在客人頁**沒有**先跳脫；設計師頁有 `escapeHtml`。這是已知問題，不要寫成客人頁會顯示純文字。
- 補一張：前端只在 `uploaded` 時重載；請求失敗吃掉。後端失敗仍 `success: true`（故意不讓清單變連不上）。

## 延時

- `msLoadAll_` 用 `getDataRange` 讀整張 `MaterialSelections`，再依案號篩。設計師開列表另跑修補與最多約 5 張、12 秒的硬碟補寫，才回 JSON。
- 設計師 API 預設逾時 60 秒（`postMaterial`）。沒有上一份清單時失敗有再試；有上一份則保留。
