# 選材每日比對與看圖快取｜實作備註

主計劃見同資料夾《選材每日比對與看圖快取.md》。總監操作 Firebase（人話、無金鑰）見《選材Firebase操作流程》。這裡才寫模組與接口。

## 模組

| 白話 | 程式對照 |
| --- | --- |
| 選材掃描／入列／每日續跑／快層補寫 | `backend/project-console/MaterialSelectionModule.js` |
| 列 Dropbox 檔（檔名、路徑、大小、時間） | `dropbox_api.js` → `listDbxFilesInFolder_` |
| 對外 action 說明 | `WebApp.js` `ACTION_DESCRIPTIONS`／GET `material_portal_cache_one` |
| 內部選材頁按鈕 | `CODING/modules/projects/designer-material-selection.html` |
| 客人「我的案場」 | `CODING/modules/accounting/customer-finance-portal.html` |
| 客人列表轉接（開頁不要打 Dropbox） | 會計轉接 → `handleMaterialPortalListTransfer_`；`msSanitizeMaterialForPortal_` 已 `skipLiveDropbox: true` |
| 客人最多補一張快層 | 會計 `margin_material_portal_cache_one` → GET `material_portal_cache_one`（只走硬碟小圖） |

沿用現有掃描匯入：人手「現在補一次」與每日排程同一套「只處理差的檔」。

## 比對鍵

**入列**

| 鍵 | 用法 |
| --- | --- |
| Dropbox 完整路徑（小寫） | 主鍵：已在表就不新增列 |
| 檔名（小寫） | 輔鍵：同案未作廢已有同檔名也略過 |
| 大小、修改時間 | `source_size`／`source_modified_at` |

**客人快層（指紋）**

`photo_cache_fingerprint` ＝ `檔名小寫|大小|時間`。  
未過期（`photo_cache_expires_at`）且指紋與現況相同 → **不搬**。過期、沒有快層、或指紋不一致才上傳差的。不要整案重傳。

## 快層寫入時機（這一刀）

| 時機 | 做什麼 | 上限 |
| --- | --- | --- |
| 每日比對／「現在補一次」入列**新檔** | 缺硬碟則從已知 Dropbox 路徑補；再把硬碟小圖上傳快層 | 每日每案約 2 張；人手單案約 6 張；仍受時間預算 |
| 設計師頁面上傳照片（已有硬碟） | 順便上傳快層 | 約 12 秒，失敗略過 |
| 客人開頁 | **只讀**已有快層／硬碟；清單請求不上傳、不打 Dropbox | — |
| 客人開頁之後背景 | 最多排隊**一張**且該筆已有硬碟 ID；指紋對上就跳過；失敗就停 | 約 12 秒 |

## 分段進度（入列）

- Script Properties：`MS_DAILY_SCAN_STATE`
- 單輪約 4 分鐘；下一案前剩不到約 25 秒就停
- `LockService` 避免兩輪重疊

## 觸發器

| 函式（白話） | 何時掛 |
| --- | --- |
| `materialSelectionDailyScan_`（每日未結案比對） | 部署後編輯器跑 `setupMaterialSelectionDailyScanTrigger_`；**不自動建** |
| `materialSelectionRetentionSweep_`（結案＋2 年清硬碟照） | 既有；仍須手動掛 |

## Firebase 桶路徑（與施工回報分開）

- 施工回報：`reports/{projectId}/{batchId}/…`
- 選材快層：`material-selection/{案號}/{選材id}/{序}_{檔名}`
- **不要**寫進 `reports/`，也勿進施工回報搬運佇列
- 下載網址帶 token（不依賴匿名讀取規則）
- **約 30 天刪檔**：須總監在 Firebase Console → Storage → 生命週期，對前綴 `material-selection/` 設 30 天刪除。Apps Script **無法**代設。

## 客人頁

- 顯示順序：未過期快層 → 硬碟縮圖 →（沒有才）載入中。開頁不 live Dropbox。
- `photos_pending`／`needs_cache_fill`：後者僅在已有硬碟、快層缺了才給背景補一張。
