# 官網商店訂單

> 最後對照程式：2026-11-27（Asia/Taipei）  
> 給人走的流程在這份。後端契約、表與動作名見 Backend_GAS `shop-orders/SPEC/SHOP_ORDERS_MVP.md`。  
> 訂單本體在官網，不在這套頁面。

**一句話：** 權限至少 3 的員工，從主控台看官網新單、報運費並寄匯款說明，確認錢入帳後才把這筆標成成立。

## 人怎麼走

1. 客人在官網結帳，得到訂單編號。這時訂單還沒成立，也不該先拿到匯款帳戶。
2. 若新單通知有接上，客人的 LINE 會先收到編號，內容只有「已收到、尚未成立」。
3. 員工開主控台。權限至少 3 才看得到「官網商店訂單」卡片。點進去是同一頁展開的訂單列表。
4. 待報價的單：運費欄一打開就是 300。確認後才寄匯款說明，狀態變成待匯款，訂單仍未成立。
5. 待匯款的單：可再寄一次說明，或按「確認收款／訂單成立」。成功後變成已成立。
6. 點一筆可看寄送地址、品項、金額與客人備註。地址整組用出貨地址；出貨是空的才改看帳單地址。
7. 黃字寫超過 7 天會刪除。那只是提醒，後端沒有到時刪單。過期的單仍留在列表，也仍可操作。

```text
客人在官網下單
  → 員工看到待報價（未成立）
  → 填運費並寄出匯款說明
  → 變成待匯款（仍未成立）
  → 確認錢已入帳
  → 訂單成立
```

### 程式對照表

| 白話（圖上寫的） | 程式對照 |
|------------------|----------|
| 客人在官網下單 | 官網 WooCommerce；這套頁面不建立訂單 |
| 員工看到待報價 | 主控台 `#/shop/orders` → `modules/shop/orders-line.html`；`ShopApi.listOrdersStaff` |
| 填運費並寄出匯款說明 | 同頁「報價並寄匯款說明」；`ShopApi.quoteAndNotifyTransfer` |
| 變成待匯款 | 後端把這筆標成已報價；畫面 `stageOf` 顯示待匯款 |
| 再寄一次說明 | 同頁「重送匯款說明」；`ShopApi.resendPayNotify` |
| 確認錢已入帳 | 同頁「確認收款／訂單成立」；`ShopApi.markPaid` |
| 訂單成立 | 後端把官網單標成已付款並改處理中；畫面顯示已成立 |
| 點開看地址與品項 | 同頁展開；`ShopApi.getOrder`；縮圖另走 `ShopApi.resolveThumbs` |
| 黃字說 7 天會刪 | 僅 `ShopApi.expireInfo` 算給畫面看；沒有刪除動作 |

舊檔 `orders-admin.html` 只負責轉到現行頁。`orders-hub.html`、`tools/shop-quote-preview/` 不是主控台現在開的那一頁。

## 畫面三種說法

| 畫面 | 意思 |
|------|------|
| 待報價（未成立） | 還沒報運費，不寄帳戶 |
| 待匯款（未成立） | 已報價。客人就算已匯款，也不自動成立 |
| 已成立（已付款） | 員工按過確認收款 |

直接開這一頁、沒有主控台登入票：畫面請人回主控台，不會列出訂單。權限低於 3、登入過期、人或票對不上、已離職，後端會拒絕，畫面用錯誤句，不會顯示成「沒有訂單」。

## 風險與等待

- 開列表容易慢：先跟主控台要登入票，後端再認人、再抓最近約 20 筆。缺商品圖時後端會逐筆補圖，畫面還要再把縮圖抓成自己能顯示的圖。有「載入中」這句，沒有逾時；連線丟出例外時會停在載入中，也不能按再試。
- 報價或重送若沒真的送到客人 LINE，彈窗仍可能像已寄出。見已知問題。
- 確認收款若官網那筆是匯款常見狀態，後端會拒絕，訂單不會成立。見已知問題。
- 員工資料會記約 6 小時。這段時間內降權或離職，仍可能看得到並標記成立。
- 主控台把登入票回給索取的視窗時，不核對是不是自己的網站。這點 F4 已記，本輪不另開。

## 已知問題（不要當成正確行為）

1. 官網匯款單常見狀態，和後端「允許確認收款」的寫法對不上（中間那個字是連字號，程式用底線）。報完價再按確認收款會被拒絕，訂單無法成立。
2. 沒有登入也能叫「把新單通知接上」。回傳可能帶出現有通知網址；若還沒接上，呼叫的人可以指定別的網址。通知網址裡常含驗證用字串。
3. 已取消、已退款，或後端不認得的狀態，員工頁仍顯示待報價，而且還能寄匯款說明。
4. 報價已經寫上、但 LINE 沒送出時，回傳仍寫「已報價並寄出」。沒有客人 LINE 也算成功。重送不管有沒有送成，彈窗多半直接出現匯款全文。
5. 同一筆再報一次運費，官網可能多加一筆運費；畫面只顯示最後寫上的那次。送出當下按鈕不會停用。
6. 列表固定最近約 20 筆，標題卻寫「共 N 筆」，沒有下一頁。更早的未完成單會看不到。
7. 畫面上的 7 天刪除沒有對應的刪除。過期單還在，也能繼續報價或確認收款。
8. 沒先報價時，畫面沒有確認收款鈕；直接呼叫後端仍可能把待付款單標成成立。
9. 客人「我的訂單／自行下單／自行取消」三頁還在，後端這三個動作回尚未接上。主控台沒有入口。有接上後端網址時，這三頁不會改出示意資料。

## 可改進

- 運費不要預設 300；空白就不要送出。
- 送出中停用按鈕，失敗要寫「說明沒送到」或「這筆已寫上、通知失敗」。
- 列表註明只顯示最近 20 筆，並可再載入。
- 已取消、已退款不要出現報價鈕。
