# 2026-08-05｜請款審核頁「測試模式」調查

## 結論

正式站（`info.tanxin.space`）請款審核頂列出現「測試模式（無登入）」**不是**前端未部署、也不是 HUB 缺 token 的 fallback，而是後端 Script Property **`ACCOUNTING_AUTH_BYPASS=true`** 仍開著。

## 證據

- 線上 `accounting_policy`：`authBypass: true`（同日查詢）
- 文案來源：`shared/js/accounting_boot.js` → `formatUserLine`：`session.devBypass` 時加 ` · 測試模式（無登入）`
- `devBypass` 來源：`accounting_api.js` `initSession` 讀 `policy.authBypass` 後走 `dev_bypass`，略過 LIFF
- HUB URL 的 `uid`／`permission` 只影響 bypass 查誰、權限幾級；**不關閉**測試模式標籤

## 與部署狀態

| 項目 | 狀態 | 與本現象關係 |
|------|------|--------------|
| accounting-gas `@259`／`@260` | 已上 | 無關；bypass 是 Property，不是今日程式 diff |
| CODING 前端暫停 upload | 未上部分 WIP | **無關**；現有正式前端本來就會依 policy 顯示測試模式 |
| LIFF ID | 已設（policy 有 `liffId`） | 有準備正式登入，但 bypass 仍優先 |

## 修復（未自動執行）

最小修復＝關閉 Property（**不必** CODING `upload.bat`、不必整包 deploy 假勤 WIP）：

1. GAS：`setAccountingAuthBypassOnce(false)`  
   或 `?page=auth_bypass&secret=…&enabled=false`
2. 使用者重新從 **官方 LINE → HUB** 開會計（清掉該分頁 sessionStorage 較穩）
3. 頂列應變：`姓名 · 權限 N`（無「測試模式」）

關閉後若 HUB 拿不到 `hub_liff_token`，會改擋「請重開 LINE」，需再查身分傳承，而非再開 bypass 當正式模式。

## 本輪未改程式／未關 Property

待使用者確認「正式改要 LINE 登入」後再關。
