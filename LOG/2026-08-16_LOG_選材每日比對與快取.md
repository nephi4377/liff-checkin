# 2026-08-16 選材每日比對與看圖快取（第一刀）

## 目的（人話）

未結案每天自己對選材夾帳，只把還沒進清單的檔加進去。客人開「我的案場」先看到空間、部位、日期；圖可以慢、破圖用人話。不要開案整包灌快層，也不要開頁去掃整個 Dropbox 夾。

## 規格

- 主計劃（含動作流程表）：`SPEC/選材每日比對與看圖快取.md`
- 實作備註：`SPEC/選材每日比對與看圖快取_實作備註.md`
- 對齊：`SPEC/21.案件毛利擴充與薪資連動.MD`、`SPEC/未來開發事項.md`、`SPEC/專案全域資料字典.md`、`SPEC/專有名詞白話對照.md`

## 程式

| 處 | 做了什麼 |
| --- | --- |
| 選材後端 | 抽出單案「只列檔、比對、只入新檔」；每日未結案可續跑（約 4 分鐘就停、記下下一案）；人手「現在補一次」仍只打這一案 |
| 列檔 | 多帶大小與時間，寫進來源大小／時間欄，給下一刀快層「一致不搬」 |
| 內部選材頁 | 按鈕改「現在補一次」；顯示最近一次自動對帳的人話 |
| 客人頁 | 標題旁「更新中」；先出文字；無圖標載入中；破圖人話；Dropbox 仍走直連圖檔 |

## 沒做

- 沒把圖完整上傳到客人 30 天快層（會拖垮一次執行時限；規格已寫人怎麼感覺）
- 沒設 LINE 預設圖文選單、沒跑長時間選單測試、沒用會整包 `git add .` 的 `CODING/upload.bat`
- 每日排程觸發器**沒自動掛**；部署後需在編輯器跑「建立每日選材比對」那支（實作備註有寫）

## 怎麼手動驗（部署後）

1. 設計師丟一張新圖到 **999** 選材夾。
2. 內部選材頁選 999，按「現在補一次」；或在後端編輯器對 999 跑一次單案比對／每日比對。
3. 內部列表與客人「我的案場」應多一筆（空間／部位／日期）；圖可能仍顯示載入中，直到硬碟副本補上。

## 風險

- 已結案且夾已搬走的，不在每日掃描。
- 剛丟檔、還沒入列：要等到當日排程或按一次「現在補一次」，客人才看得到。

## 第二刀（同日）— 客人看圖快層最小能動

### 做到哪

- **寫入**：每日比對／「現在補一次」入列新檔時，缺硬碟就補、再上傳小圖快層（有上限）。設計師在頁面上傳也會順便補快層。
- **比對**：`檔名|大小|時間` 對得上且未過期 → **真的跳過不搬**。
- **客人開頁**：只讀快層或硬碟縮圖；清單請求不打 Dropbox、不整案上傳。畫面出齊後最多背景補**一張**（必須已有硬碟；失敗就停，不改成「連不上」）。

### 改了哪些檔

- `backend/project-console/MaterialSelectionModule.js`、`WebApp.js`、`FirebaseHandler.js`（註解：選材前綴勿進施工回報搬運）
- `backend/accounting-gas/master/CustomerFinanceModule.js`、`WebApp.js`（轉接「補一張」）
- `CODING/modules/accounting/customer-finance-portal.html`、`shared/js/accounting_api.js`
- 規格／字典／施工回報路徑說明／本 LOG

### 沒做／要總監在 Console 設

- 每日觸發器仍不自動掛（見下方部署段）
- **Firebase Storage 生命週期 30 天程式無法代設**：請到 Firebase Console → Storage → 生命週期，對 `material-selection/` 設 30 天後刪除。沒設的話快層檔會一直留在桶裡（試算表仍會當過期、下次才重傳）。
- 沒做瀏覽器直傳整包。

### 999 怎麼驗（部署後）

1. 丟一張新圖到 999 選材夾，內部頁按「現在補一次」。
2. 內部與客人清單應多一筆文字（空間／部位／日期）。
3. 客人圖：有快層或硬碟縮圖就應出圖；沒有則「載入中」，整頁不要變連不上。
4. 再按一次「現在補一次」：不應把同一張再灌進快層（提示沒有新照片／快層仍有效）。
