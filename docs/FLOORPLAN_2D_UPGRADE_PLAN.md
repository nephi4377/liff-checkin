## 升級項目（依設計師價值排序）

### 1. 智能吸附與對齊參考線

| 項目 | 說明 |
|------|------|
| **問題** | 櫃體、沙發、門片需對齊牆或彼此邊緣；僅靠目測與 2cm 步距慢且易歪。程式註解曾預留物件吸附但未實作。 |
| **提案** | **(已做 S)** 拖曳時以外框 AABB 做邊／中心吸附（10cm 閾值，Shift 全關吸附）。**(待做 M)** 拖曳中顯示洋紅虛線參考線；牆體頂點、繪圖中點亦可列入參考目標。 |
| **工作量** | S（吸附核心）＋ M（參考線 UI） |
| **風險** | 低～中：旋轉物件用 AABB 略粗；參考線需效能與 z-index 規劃。 |

### 2. 牆段／開間尺寸標註（Dimension Lines）

| 項目 | 說明 |
|------|------|
| **問題** | 僅有選取物件上的 `寬×深 cm` 小標；提案圖常需牆長、門洞淨寬、房間開間。 |
| **提案** | 選取牆區域或兩點後，自動產生鏈式標註（cm＋可選尺）；標註跟隨 `drawnAreas` 存 JSON；PNG 匯出含標註層。 |
| **工作量** | M～L |
| **風險** | 中：與現有工程標註（annotation）職責需區分；密集標註時可讀性。 |

### 3. 客戶用圖面匯出（比例尺＋圖層）

| 項目 | 說明 |
|------|------|
| **問題** | `html2canvas` PNG 無比例尺、無北向／圖例；設計師仍手動加在 PPT。 |
| **提案** | 匯出前可勾選：比例尺（例 100cm 尺條）、圖層（牆／天花／家具）、施工面積備註；與現有浮水印並存。 |
| **工作量** | M |
| **風險** | 低～中：html2canvas 對大畫布（3500²）可能慢或記憶體偏高。 |

### 4. 牆體繪製體驗（對齊 3D）

| 項目 | 說明 |
|------|------|
| **問題** | 牆＝多點閉合多邊形，非「點兩端拉一段」；厚度僅數字輸入，拖曳中難想像實體帶（3D 已用 `drawnAreas.type==='wall'`）。 |
| **提案** | 單段牆工具（起終點＋厚度帶預覽）；顯示當前段長（cm）；完成後仍可進 vertex 編輯；與 `wall-thickness-input` 及 3D 厚度一致。 |
| **工作量** | M |
| **風險** | 中：新牆資料模型需與既有 `calculateWallPath`／3D `buildLayout3DDescriptor` 相容或轉換。 |

### 5. 格線與吸附步距（5／10 cm） ✅（FLOORPLAN-2D-2）

| 項目 | 說明 |
|------|------|
| **問題** | `#grid-layer` 固定 50px 格、無法關閉；與 2cm 拖曳步距不一致，對齊「整十公分」仍靠手感。 |
| **提案** | 工具列：顯示格線、主格 50cm／次格 10cm；吸附步距 1／5／10 cm（與 Shift 停用連動）。 |
| **工作量** | S |
| **風險** | 低。 |
| **狀態** | **已完成（第一版）**：格線顯示開關（localStorage）；吸附步距 2／5／10 cm（預設 2）；`LP_core.snapTranslationToGrid`。次格 10cm 視覺仍待後續。 |

### 6. Undo 粒度與連續操作 ✅（FLOORPLAN-2D-2）

| 項目 | 說明 |
|------|------|
| **問題** | 拖曳每 mouseup 一筆歷史；長拖曳易塞滿 50 步。牆頂點連拖可能多步。 |
| **提案** | 拖曳／縮放／vertex 拖曳以「手勢開始～結束」合併為一步；可選顯示歷史步驟簡述。 |
| **工作量** | S～M |
| **風險** | 低：需審視所有 `saveState()` 呼叫點。 |
| **狀態** | **已完成**：`LP_layout_history.createHistoryGestureCoalescer`；櫃體拖曳／縮放／牆頂點／標註／透明度滑桿手勢合併為單步 undo。 |

### 7. 平板 2D 精簡模式（非 3D 取替）

| 項目 | 說明 |
|------|------|
| **問題** | `Mobi` UA 直接遮罩，現場量圖／擺家具無法用。3D 已有 touch 漫遊，2D 完全缺席。 |
| **提案** | 平板寬度允許 2D：雙指縮放畫布、單指拖物件（pointer events）、精簡工具箱；手機仍維持引導 LINE。 |
| **工作量** | L |
| **風險** | 中～高：與現有 mouse 事件模型並存、測試矩陣大。 |

### 8. 大量元件效能

| 項目 | 說明 |
|------|------|
| **問題** | 每櫃 DOM 節點＋拖曳時全掃描碰撞／吸附；大案（>80 件）可能卡頓。 |
| **提案** | 空間索引（grid hash）做碰撞與吸附候選；靜態元件 `will-change`／減少 `renderAllCabinets`；可選「簡化模式」隱藏 SVG 細節。 |
| **工作量** | M |
| **風險** | 中：需 Vitest／e2e 基準（拖曳 FPS 或步驟時間）避免退化。 |
