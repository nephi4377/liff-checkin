# 每輪必查維度（補完計劃）

每個選定功能除了「對齊／新建 SPEC」外，**一定要過這三塊**：交叉出錯、延時判定、可改進。  
讀碼為主（靜態推演＋契約對照）；能本地開站就順便點；**不要**假裝已對正式站做真人壓力測。

產出寫進 `TOS/規格巡檢回報.md` 本輪對應表；B0／B1 仍走 Slack `#程式撰寫`。

---

## A. 交叉出錯可能性（Cross-fault）

問：人連做兩步、兩頁、或前後端各失敗一次時，系統會不會講錯話、寫錯資料、或卡死？

| 檢查項 | 怎麼判定「有風險」 | 常見落點 |
|--------|--------------------|----------|
| A1 失敗當空 | 讀取拋錯卻顯示「沒資料／0 筆」 | 列表、待辦、名冊 |
| A2 雙寫／雙源 | 同一事實兩處寫入或兩套數字，失敗只回滾一邊 | Hub＋GAS、Sheets＋快取 |
| A3 身分交叉 | 換人／過期 token／iframe 與父頁身分不一致仍繼續寫 | LIFF、Hub 傳承 |
| A4 連點／重送 | 無鎖定或無冪等，連點變兩筆 | 打卡、請款、送出 |
| A5 部分成功 | 上傳成功但寫表失敗（或相反），畫面只報一邊 | 附件、OCR、日報照片 |
| A6 跨模組狀態 | A 頁改完 B 頁仍舊快取／舊狀態無失效 | 會計↔主控台、排班↔出勤 |
| A7 權限邊界 | 前端擋了後端沒擋，或規格與畫面門檻不一致 | 財務頁、商店後台、撤回／取消 API |
| A8 空／失敗／無權限未分開 | 三種狀態同一文案或同一 UI | 任何列表／詳情 |
| A9 失敗當成功 | API `status:success` 但寫入失敗／業務拒絕；或畫面樂觀成功（如 no-cors） | 打卡佇列、審核、送出 |
| A10 文案≠狀態機 | 頁面寫「可先報備」但後端只有另一假別會進報備 | 假勤、表單說明 |
| A11 字串對不上清不掉 | 寫入帶時段／後綴，清除只比短名 | 銷假清班表、標籤移除 |

**最低要求**：本輪每個功能至少寫出 **2 個**交叉情境（「若…則…」），標「已防／未防／不明」。未防 → 依嚴重度進 B0～B3。

### F1 測跑常見樣態（之後各階也要聯想）

- 前置佇列／暫存寫失敗仍回「已送出」→ 優先 **A9／B1**  
- 離線先示成功、雲端尚未有 → 標已防但要在 SPEC「風險」說清楚  
- 整表 `getDataRange` 去重或列表 → 延時至少 **中／高**

## B. 操作易延時判定（Latency）

問：這個操作**容易變慢**嗎？慢的時候人看得到、等得下去嗎？

### B-門檻（白話）

| 類型 | 偏慢起點 | 很糟 |
|------|----------|------|
| 開頁／首次列表 | 約 **3～5 秒**仍無可讀內容 | 空白或只轉圈無下文 |
| 單次送出（打卡、送審） | 約 **3 秒**無「已收到」回饋 | 可連點、無結果 |
| 掃表／跨月／未篩選大查詢 | 程式有整表掃描、無分頁／無條件仍全抓 | 員工開頁必等很久 |
| 連續多支 API | `Promise.all` 很多支且任一慢就整頁卡 | 無個別失敗處理 |

### B-檢查項

| 檢查項 | 怎麼判定 |
|--------|----------|
| B1 有無逾時 | fetch／GAS 呼叫有沒有 timeout 或中止路徑 |
| B2 有無重試 | 短暫失敗會不會自動再試一次；人能不能按再試 |
| B3 有無先給可看的 | 骨架、快取先顯示、或「更新中」狀態區 |
| B4 有無避免整表 | 預設查詢是否過寬；註解是否已承認「整表太慢」卻仍預設掃 |
| B5 慢路徑有沒寫進 SPEC | SPEC 是否標「預期可能慢的操作」與人話等待 |

**最低要求**：每個功能給 **延時等級**——`低`／`中`／`高`（易延時），並寫 1 句依據（例如：未指定廠商仍掃收支月分頁）。`高` 且無人話等待／無重試 → 至少 B1。

對齊 `human-comfortable`「載入與等待」；細節不重複抄那份，只做判定與回報。

## C. 其他可改進（Improve）

問：就算沒壞，這個角色還會自然想要什麼？結構能不能更穩？

| 檢查項 | 例子 |
|--------|------|
| C1 動作閉環 | 點了→進行中→成功／失敗；缺一段就記 |
| C2 人話與下一步 | 錯誤有沒有教人怎麼修；成功後下一步清不清楚 |
| C3 SPEC 結構 | 缺流程圖、缺對照表、前後端互指斷了 |
| C4 可測性 | 有無既有測試／本地 bypass；關鍵路徑完全無法測要註明 |
| C5 與字典／權限一致 | 欄位名是否對 `專案全域資料字典`；權限是否與 SPEC 一致 |
| C6 重複實作 | 同事先做兩套 API／兩套快取 |
| C7 無障礙與手機 | 主按鈕過小、只靠顏色、僅桌機可用卻給現場用 |
| C8 升級機會 | 少一步操作、預設值、合併兩次讀表等（偏 B3／建議） |

**最低要求**：每個功能至少 **1 條**可改進（可為「暫無，已對齊」＋一句理由）。可改進預設 B3；若已造成錯資料／誤導 → 升為 B0／B1。

## 寫進回報時的欄位

本輪每個功能建議固定三小段（可表可條列）：

```text
交叉出錯：A? …（已防／未防／不明）
延時判定：低｜中｜高 — 一句依據
可改進：C? …
```

有「未防」的交叉出錯或「高」延時且無配套 → 進入 Bug 表並視等級 Slack。
