# 自動化規格管理｜實作備註

給執行本 Skill 的 Cloud Agent／Automation。  
（2026-11-11 F1 測跑後加硬：分支順序、雙 repo PR、收工自檢。）

## 環境

- 多倉庫：**liff-checkin** + **Backend_GAS**。
- 前端根目錄不要 `npm install`；多數輪次以讀碼為主，不必開站。
- 排程是 [Cursor Automations](https://cursor.com/automations)，不是 repo cron。

## Git 工作流（務必照順序）

### 為什麼要分兩條線

| 線 | 分支 | 放什麼 |
|----|------|--------|
| 狀態 | `spec-audit/state` | **只**持續更新 `TOS/規格巡檢回報.md`（指針＋累積待修） |
| 產品 SPEC | `cursor/spec-audit-…`（各 repo） | SPEC 升級／新建；開 `[規格管理]` PR |

若把指針只 commit 在未合併 SPEC PR → 下輪從 main 開工會重跑 F1。

### 建議指令順序

```bash
# 1) 讀狀態
cd liff-checkin
git fetch origin spec-audit/state main
git checkout spec-audit/state
git pull --ff-only origin spec-audit/state
# 讀 TOS/規格巡檢回報.md → 記下本輪階段與功能

# 2) SPEC 工作（不要在 state 上改 SPEC）
git checkout main && git pull --ff-only origin main
git checkout -b cursor/spec-audit-<主題>-YYYYMMDD-a36f
# …改 SPEC、commit、push、開 PR
# Backend_GAS 同樣開分支／PR（若本輪有後端 SPEC）

# 3) 回寫狀態（最後）
git fetch origin spec-audit/state
git checkout spec-audit/state
git pull --ff-only origin spec-audit/state
# 編輯 TOS/規格巡檢回報.md（含 PR URL、下一階指針）
git add TOS/規格巡檢回報.md
git commit -m "chore(spec): advance audit rotation …"
git push origin spec-audit/state
```

可選：把 state 上的回報檔 `git checkout spec-audit/state -- TOS/規格巡檢回報.md` 再 commit 進 SPEC PR 當鏡子。

### 雙 repo

功能跨前端＋GAS 時：

- `liff-checkin` 與 `Backend_GAS` **各一** `[規格管理]` PR  
- 回報「近期」兩條連結都寫  
- 只改一邊要在回報註明「另一邊無對應 SPEC／本輪略」

## Slack（B0／B1 必做）

- 頻道：`#程式撰寫`（`C0AULCX9SLT`）
- 同輪多筆 B0／B1 併一則即可；帶 PR URL
- 失敗重試一次；仍失敗寫進回報「Slack 未送出」

## SPEC 升級策略（測跑後補強）

| 落差長相 | 做法 |
|----------|------|
| 小段過時（旗標名、少一個 action） | 小改＋「最後對照程式」日期 |
| API／狀態名整段錯（如仍寫已廢的 `supplement`） | **重寫**主流程與對照表，勿 salami 假對齊 |
| 多份 SPEC 互相打架 | 以程式為準改「現行行為」檔；舊絕對句刪或標廢止；互指路徑 |
| 明顯 bug | SPEC 寫「已知問題」；Bug 表＋Slack；**不要**寫成正確規格 |

## 讀碼建議順序（單一功能）

1. 入口頁／主 JS  
2. API action／GAS  
3. 既有 SPEC（前後端）  
4. 人怎麼走、成功／失敗／空、權限  
5. 交叉（含：**失敗當成功**、文案與狀態機不一致）  
6. 延時（整表、timeout、重試、乾等）  
7. 可改進  
8. 寫 SPEC → PR → 最後才推 state → Slack  

## 收工自檢

- [ ] `origin/spec-audit/state` 指針已推進  
- [ ] 回報有 PR URL（若有開）  
- [ ] B0／B1 已 Slack 或註明未送出  
- [ ] 該動的前後端都動了或已說明略過  
- [ ] 未部署、未覆寫真人巡檢回報  

## 與真人巡檢並存

- 回報檔不同；可同時開 Automation。  
- 規格管理建議每天 1 次，避免與真人巡檢搶額度。
