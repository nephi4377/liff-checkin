# human comfortable

**管**：真人會看、點、填、讀的介面。  
**不管**：Agent 回覆格式、log／JSON 當預設畫面。

## 寫計劃：先講動作，再談程式

計劃一開始只寫**人怎麼走完一件事**。通過標準：不寫 code 也能看懂、能點頭。

| 寫什麼 | 怎麼寫 |
| --- | --- |
| 目標 | 一句話：這次要讓人完成什麼 |
| 動作流程表 | 點什麼 → 畫面立刻怎樣 → 最後成功／失敗怎樣 → 下一步 |
| 不寫進主計劃 | 函式名、檔名、CSS class、API、實作清單 |

程式要記的內容放同資料夾 [`實作備註.md`](實作備註.md)，主計劃只留流程與目標。

### 動作流程表（每個主功能一張）

| 步驟 | 人做什麼 | 畫面呈現 | 結果／下一步 |
| --- | --- | --- | --- |
| 1 開始 | （例如：按「送出」） | 立刻知道「有收到」（按鈕變處理中／不能連點） | — |
| 2 進行中 | 可等、或去做別的（看情況） | 「處理中」；長時間可顯示進度（如 2/5） | — |
| 3a 成功 | 看結果 | 輕提示或摘要已更新；按鈕恢復可再操作 | 清楚下一步（留在這／回上一層／看明細） |
| 3b 失敗 | 看說明、再試或改 | 人話說明＋怎麼修；按鈕可再按 | 人知道卡在哪、能繼續 |

**閉環**：每個主動作都要走完「開始 → 進行中 → 結束」，不能停在轉圈或沒下文。

## 先記：人會做不到的事

設計時假設使用者**做不到**下面這些，介面要代勞或降要求：

| 做不到 | 介面怎麼補 |
| --- | --- |
| 同時想很多事、記不住步驟 | 一屏一事；下一步寫清楚；預設值、自動帶入 |
| 在雜亂畫面找重點 | 留白、主從分明；同區**一個**主按鈕 |
| 讀小字、辨顏色、精準點小目標 | 字夠大；紅綠須配文字；觸控區夠大、間距夠 |
| 懂錯誤碼與術語 | 人話；錯在欄位旁；告訴怎麼修 |
| 猜系統有沒在跑 | 點了立刻有回饋；整段閉環見上表 |
| 承受犯錯、怕搞砸 | 可反悔；危險操作確認且預設取消；少擋全屏 |

## 三大原則

| 原則 | 必做 |
| --- | --- |
| **看哪裡很清楚** | 標題說這頁在做什麼；摘要優先、細節收起；少用功能藏進階 |
| **要做什麼很簡單** | 主功能不藏三層；空／錯／成功都有人話；表單有可見標籤；點了不連點 |
| **做錯了不挫折** | 禁錯誤碼、裸 JSON、只靠顏色當唯一提示；刪除／覆蓋要確認或還原 |

**頁面骨架**：`[標題]` → `[可選一行狀態]` → `[一個主按鈕]` → `[摘要／內容]`

版面與樣式實作見 [`實作備註.md`](實作備註.md)。

## 做完自檢（用人能做的事檢查）

- [ ] 主計劃裡有動作流程表，不是一堆程式事項？
- [ ] 每個主動作都有開始→進行中→結束（成功或失敗）？
- [ ] 不讀說明書也知該點哪、下一步是什麼？
- [ ] 失敗時人知道怎麼修、能再試？
- [ ] 危險操作可反悔？
- [ ] 手機／長輩仍讀得清、點得到？
- [ ] 預設畫面沒有 log、整表灌爆？
