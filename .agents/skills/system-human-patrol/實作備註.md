# 真人巡檢｜實作備註

給執行巡檢的 Agent（排程或手動）。

## 先認入口（與 SKILL 一致）

| 誰跑 | 看什麼 | 回報去哪 |
|------|--------|----------|
| **系統路徑**（Cloud Agent／Automations／每 2 小時） | **營運系統**：主控台、出勤、會計、載入／送出閉環、失敗當空 | 對話結論＋覆寫 `TOS/巡檢回報.md` 的「本輪」（累積「待你決定」） |
| **當下工作路徑**（聊天／手動 `/system-human-patrol`） | **本對話正在做的事**（FAQ、案例、SEO、門市…） | **立刻寫在對話裡**；不要覆寫 `TOS/巡檢回報.md` |

可**讀** `TOS/巡檢回報.md` 來定視角。  
- 系統路徑：避開剛查過的同頁／同 API。  
- 當下工作路徑：若那就是對話裡的當下工作則繼續查，不要改去無關營運頁。  
**不要**覆寫根目錄 `下一輪該改什麼.md`（可留手動規劃）。  
巡檢回報檔本身不是產品。選點細節見 `SKILL.md` 兩條「怎麼選切入點」。

排程不是 repo 裡的 cron，而是 Cursor Automations。可貼指示：`TOS/營運系統真人巡檢_自動化指示.md`（必須走系統路徑）。Dashboard：`TOS/營運系統真人巡檢_切換步驟.md`。

## 環境

- 需要多倉庫：**liff-checkin**（前端）＋ **Backend_GAS**（後端）。
- 前端根目錄**不要** `npm install`（根 package 含 Playwright，會拖慢 Build）。靜態站用既有說明即可。
- 後端部署用各子目錄 `upload.bat`／`clasp`；未判定 P0 且未過 deploy-runbook 閘門 → 不上正式。

## P0 部署檢查清單（窄範圍）

- [ ] 只改與本條發現直接相關的檔；一次一事
- [ ] 未碰：假勤政策、獎金切換、全公司 LINE 選單、權限模型、資料表結構
- [ ] 失敗／空／載入狀態已分開；該有重試或人話錯誤
- [ ] 已載入並遵守 `deploy-runbook`（SPEC／LOG／備份／部署／回報）
- [ ] 對話裡已說「已修已上線」與怎麼驗（系統路徑那輪才把同一狀態寫進巡檢回報檔）

## P1 分支

- 名稱：`patrol/<簡短主題>-YYYYMMDD`
- push 分支；可開 PR，標題含 `[巡檢P1]`
- **不** merge main、**不** clasp／upload 正式，除非使用者另說

## 摘要三行（每次結尾必寫）

```text
P0 已上線：N 件（一句話列表或「無」）
P1 分支待看：連結或「無」
待你決定（P2／P3）：N 件（一句話或「無」）
```
