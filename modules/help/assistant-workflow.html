助理工作流程說明

先知道為什麼、問誰、依什麼順序、做到什麼程度，再執行。這是流程說明與訓練頁，不是正式任務派工或排程系統。

跳到段落

共同原則更新優先序選材與樣品文件版本追加減與款項照片與日誌丈量與會議驗收與結案保固與維修一般行政進場與安裝家具配送報價前置進度異常其他事務

所有助理事務共用的六個確認點

收到交辦確認案件與目標
↓
向內確認範圍、品項、責任人
↓
向外確認供貨、工期、可行時間
↓
交叉核對現場與人員不衝突
↓
對客確認提供已確認的選項
↓
同步留痕結果、證據、下一步
不替別人先承諾廠商、司機或客戶尚未確認前，不把預估時間說成確定時間。
聯絡過不等於完成必須取得明確答覆；未回覆要留下追問時間與下一次追蹤點。
回報要能接著做不要只寫「已詢問」，要寫對方回覆、卡點、建議方案與待誰決定。
案件一律可追溯使用正確 project_id，保存對話、照片、報價或文件位置與版本。

目前更新優先序

先把高頻、跨多人、容易漏接的流程寫完整；每次迭代只深化一種事務並加入完成條件與異常分支。

P0｜優先建立完整流程

進場／安裝協調、家具配送、報價前置資料、案場進度與異常追蹤。

先補齊：觸發條件、必要輸入、逐步作法、訊息範本、完成條件、逾時與取消處理。

P1｜第二階段

選材送樣、圖面與文件版本、追加減／請款協助、施工照片與日誌歸檔。

P2｜後續擴充

驗收結案、保固維修、會議／丈量準備、跨案共用行政事項。

P0 常用流程

進場／安裝時間協調 P0

適用窗簾、家電、五金、設備安裝及需與客戶約時間的收尾工作。

開始前要有project_id、施工項目、內部承辦人、希望完成期限
最後要產出各方確認的日期時段、現場配合事項、對客回報紀錄
  1. 向設計師或內部承辦人確認本次施工範圍、現況及不可安排時段。
  2. 詢問執行廠商至少一個可進場日期、時間、預估工時與人數。
  3. 核對現場是否可施工：鑰匙、人員、其他工種、電梯或管委會限制。
  4. 把已確認的可行選項提供客戶，不先指定客戶必須接受某一時段。
  5. 客戶確認後，同步廠商、設計師與現場相關人員，並記錄最後版本。
完成條件：客戶與執行者確認同一日期時段，現場限制已排除，相關人員都收到一致資訊。
不可直接完成：只有詢問、只有單方答應，或仍寫「時間再確認」。

卡住或變更時怎麼處理

異常發生後回到「重新確認」，原本時段不能沿用為有效承諾；未再次取得各方一致答覆前，狀態都不是「已確認」。

廠商未回覆
  1. 記錄聯絡時間、方式及詢問內容，不自行推定可進場。
  2. 設定下一次追蹤時間；若已影響期限，立即回報內部承辦人。
  3. 由內部承辦人決定改找窗口、備選廠商或調整目標日期。
狀態：待外部回覆。取得明確日期前不可對客承諾。
任何一方要求改期
  1. 先記錄提出者、原因及原時段，明確標示原約定已失效。
  2. 重新核對廠商、現場與客戶，不可只通知其中一方。
  3. 新時段三方確認後，再同步設計師及所有受影響人員。
狀態：重新協調。新時段確認後才可改為已確認。
施工或安裝取消
  1. 確認是暫停、延後或確定取消，以及由誰做成決定。
  2. 通知廠商、客戶、現場及內部承辦人，取消車趟或管委會申請。
  3. 記錄已發生成本、影響範圍與後續是否需要重新安排。
狀態：已取消或待重新安排，不可標成已完成。
客戶不同意提供的時段
  1. 詢問客戶可接受的日期區間與不可安排條件，不要求勉強接受。
  2. 將客戶條件帶回廠商及現場重新媒合，必要時請內部承辦人取捨。
  3. 只回覆重新核對後可行的選項，直到各方同意同一時段。
狀態：待客戶確認或重新協調，不把拒絕視為取消。
每次異常留痕：保存 canonical project_id、承辦／操作者 employee_id、發生與聯絡時間、目前狀態、對話或文件證據、待誰決定及下一次追蹤時間。流程仍依「指派 → 執行 → 回報 → 審核／退回」交接，不以口頭轉述取代紀錄。

家具／材料／設備配送 P0

適用成品家具、訂製品、材料與設備送到案場，包含外車與搬運協調。

開始前要有品項、數量、規格、收貨地點、內部確認人
最後要產出到貨日、車趟、人力、客戶時段、簽收與異常紀錄
  1. 先向內部確認正確品項、數量、尺寸、組裝需求及是否可拆件搬運。
  2. 向供應商確認實際完成／到貨時間；未完成前不可先約外車。
  3. 確認案場收貨條件：地址、樓層、電梯、停車、保護、進場限制與聯絡人。
  4. 依貨量與限制向外車司機確認車型、人力、日期、時段與費用。
  5. 整合供應商、司機及現場可行時間後，再向客戶確認。
  6. 配送完成後取得照片或簽收結果；缺件、破損或無法入場要立刻回報。
完成條件：品項正確送達指定位置並完成簽收，異常已記錄且有明確處理責任人。
不可跳步：品項尚未確認或供應商未確認到貨，就先向客戶承諾配送時間。

配送異常怎麼處理

先停止簽收或搬運到下一階段，保留現場證據並通知內部承辦人。責任、費用與新時段尚未確認前，不替供應商、司機或客戶做決定。

缺件或數量不符
  1. 依送貨單逐項清點，拍攝已到品項、包裝標示及缺少位置。
  2. 請供應商確認缺件原因、補件內容與最早可補送時間。
  3. 回報內部承辦人，由其確認可否先簽收已到品項及是否影響安裝。
狀態：部分到貨／待補件；補件到場並再次清點前不可標示配送完成。
破損、髒污或規格不符
  1. 先不要拆除標籤或繼續安裝，拍攝全景、瑕疵近照、外箱與品項標示。
  2. 在簽收單註記異常；是否拒收、暫放或退回，由內部承辦人與供應商確認。
  3. 記錄換貨、修補或重製方案、責任窗口及預計完成日。
狀態：異常待判定／待改善；未複查合格前不可視為完成。
超材或尺寸無法搬運
  1. 停止強行搬運，量測貨物、門洞、轉角、樓梯與電梯的實際淨尺寸並拍照。
  2. 請供應商確認能否拆件、現場組裝或改用吊車；不得自行拆改成品。
  3. 將安全、費用、管委會申請及工期影響交由內部承辦人決定。
狀態：無法搬運／待方案確認；新方案核准前暫停進場。
無電梯或電梯不可用
  1. 確認樓層、樓梯淨寬、轉角、搬運距離及電梯停用原因與可恢復時間。
  2. 請司機／搬運方重新評估人力、樓層費、工時與是否能安全搬運。
  3. 新增費用或改期先回報內部承辦人，核准後才能向客戶確認。
狀態：待搬運條件確認；不可要求現場人員臨時冒險搬運。
現場無法進場或收貨
  1. 確認原因是無人開門、地址／入口錯誤、管制、無停車位或其他工種阻擋。
  2. 立即聯絡現場窗口與內部承辦人，記錄抵達時間、等待時間及現場照片。
  3. 由內部承辦人決定等待、改送暫存點、退回或另約，不自行留置貨物。
狀態：到場未交付；貨物去向與保管責任必須明確。
需要二次配送
  1. 整理第一次未完成原因、已送／未送品項、貨物現況及目前保管地點。
  2. 確認二次車趟、人力、費用與責任歸屬，再重新核對供應商及現場條件。
  3. 依「供應商 → 司機／搬運 → 現場 → 客戶」順序取得新時段的一致確認。
狀態：待二次配送；第二次完成簽收與異常複查後才能結案。
每次異常留痕：保存 canonical project_id、承辦／操作者 employee_id、到場與發現時間、品項及數量、目前狀態、照片／送貨單／對話證據、貨物保管位置、待誰決定與下一次追蹤時間。流程仍依「指派 → 執行 → 回報 → 審核／退回」交接；異常處理完成後須由指定審核者確認，不以司機離場或貨物留置視為完成。

最後要產出service_request_id、保固判定依據、處置與約修紀錄、維修前後證據、驗證結果及審核紀錄
  1. 建立維修案件：先核對 canonical project_id，為本次問題建立唯一 service_request_id；記錄回報人、接案者 employee_id、收到時間、問題位置、品項與客戶原始描述，不先改寫成原因或責任。
  2. 蒐集可判讀證據：取得全景、近照、影片、聲音或錯誤訊息，追問首次發生時間、頻率、使用情境、是否持續及已嘗試動作；漏水、焦味、漏電、鬆脫或其他風險先請客戶停用／遠離，再立即升級指定主管。
  3. 查核保固資料：依 project_id 找出合約、追加減、驗收／交接日、設備型號、保固書、供應商及過往維修紀錄，核對有效版次、期間、範圍與排除條件；資料不足只能標「待判定」。
  4. 完成內部判定：將事實、證據與文件提交指定設計師或主管，由其書面確認保固內／保固外／待現勘、責任界面、是否收費及下一步；助理不得自行承諾免費、認錯或代替技術判斷。
  5. 同步客戶與追蹤點：只說明已確認事實、目前判定、需補資料及下一次更新時間；尚未核准的到場日、費用、材料與完成日不得寫成確定承諾，客戶未回覆須保留追蹤時間。
  6. 交叉確認檢查／維修：依核准處置確認內部負責人 employee_id、外部聯絡節點、可行時段、材料、進入限制及客戶同意；三方時段未一致前維持「協調中」，不視為已安排。
  7. 追蹤處置與證據：依 service_request_id 保存到場、檢查結果、實際處置、材料／零件、卡點、改期及前後照片；外部人員表示完成只能標「待驗證」，不可直接結案。
  8. 驗證、回報與送審：由指定驗證者確認功能、外觀、安全及是否需要觀察期，取得客戶接收回覆；未改善或復發則退回補正，通過後歸檔判定、費用依據、維修報告、證據與保固影響，再由審核者結案。
完成條件：保固狀態與處置已有核准依據；安全風險已受控；檢查／維修完成並有前後證據及驗證結果，客戶已收到結果；保固外或無法處理時也須有核准原因與明確下一步，最後由指定審核者通過。
不可直接完成：找不到案件仍猜測保固、證據不足先判責、助理承諾免費或賠償、風險未升級、三方時段尚未確認、只憑外部口頭回報結案、未驗證功能，或維修資料未依 project_id 歸檔。
全程留痕：依「指派 assigned → 執行 in_progress → 回報 reported → 審核通過 approved／退回 rework」保存 canonical project_id、service_request_id、接案／判定／追蹤／驗證／審核者 employee_id、收件／聯絡／到場／補正／結案時間、狀態、保固文件版次、客戶原始回報、前後證據、費用依據、維修報告及退回原因。

P2｜跨案件一般行政協助

適用同一批次中彙整多個案件的文件、資料核對、狀態追問與交接。批次可共用 admin_batch_id，但每筆案件仍以 canonical project_id 獨立追蹤；純公司行政不在本流程，也不得借用假案號。

跨案件行政批次 P2

開始前要有admin_batch_id、交辦者與執行者 employee_id、目的、截止時間、案件 project_id 清單、允許動作與輸出格式
最後要產出逐案處理清單、來源與版本、完成／卡點狀態、證據連結、交接對象與逐案審核結果
  1. 確認批次範圍：向交辦者確認目的、優先順序、截止時間、輸出格式、允許聯絡對象及不可代決事項；建立 admin_batch_id，保存交辦者與執行者 employee_id。
  2. 拆成逐案項目：每個項目只綁定一個 canonical project_id，列出工作內容、負責人、期限與預期證據；同一文件涉及多案時也須分列，避免更新甲案卻覆蓋乙案。
  3. 檢查權限與最小資料：確認執行者可查看及處理各案，只蒐集本次必要的客戶、合約、金額或聯絡資料；無權限、案件不明或收件人不確定時停止該列並回報，不跨案複製敏感資訊。
  4. 取得有效來源：逐案記錄資料來源、檔名／連結、版次、取得時間及提供者 employee_id；聊天室轉述、舊表或檔名相似不能直接當最新資料，有衝突須請案件負責人指定有效版。
  5. 依授權執行：按逐案清單整理文件、追問缺項、更新核准欄位或準備交接；助理不得自行修改價格、合約、付款狀態、設計決議或對外承諾，需決策項目標記「待指定人確認」。
  6. 逐案交叉核對：檢查 project_id、客戶／案件識別、版次、日期、金額、附件、收件人與動作是否一致，並確認沒有重複、漏列或跨案附件；核對者以 employee_id 留痕。
  7. 分列回報與交接：每案分別標示完成、待回覆、受阻或退回，附結果、證據、卡點、下一位負責人 employee_id 與期限；不得只報「整批完成」，未完成項目須清楚列出追蹤點。
  8. 審核與歸檔：指定審核者逐案通過或退回；退回只補正該 project_id 項目並保留原因與舊版，全部項目通過、經授權取消或完成責任交接後，才能關閉批次。
完成條件：批次內每個項目都有真實 project_id、有效來源、處理結果、操作者、時間、狀態與證據；待辦已指定下一位負責人及期限，各案均通過審核、經授權取消或完成明確交接。
不可直接完成：用假案號收納公司行政、把多案資料放在同一列、未確認權限即匯出、沿用舊版、跨案貼錯附件、助理代改金額／決議、只寫「整批完成」，或以部分案件通過掩蓋其餘未完成項目。
全程留痕：批次與每個案件項目均依「指派 assigned → 執行 in_progress → 回報 reported → 審核通過 approved／退回 rework」保存 canonical project_id、admin_batch_id、交辦／執行／提供／核對／審核者 employee_id、各步時間與狀態、來源版次、輸出、證據、交接對象及退回原因。
