# 營運系統真人巡檢｜自動化指示（可貼 Settings）

把下面「指示正文」整段貼進 Cursor Automation 的指令／prompt 欄。  
名稱建議：`營運系統真人巡檢`。觸發：**每 2 小時**。環境：多倉庫 **liff-checkin + Backend_GAS**（與已成功的個人環境相同即可）。

---

## 指示正文

```text
你正在執行「營運系統真人巡檢」。必須遵守專案 Skill：system-human-patrol
（路徑 .agents/skills/system-human-patrol/；先讀 SKILL.md、perspectives.md、實作備註.md）。

環境：liff-checkin 與 Backend_GAS 都在工作區。前端根目錄不要 npm install。

步驟：
1. 讀 TOS/巡檢回報.md，決定本輪視角（上一輪的下一個；無紀錄則從總監開始），
   並避開上一輪已查的同一頁／同一 API（除非中間有產品向新提交或標了要再驗）。
2. 載入 ui-flow、human-comfortable。只深挖 1～2 個切入點（視角偏好 × 最近提交 × 反模式）。
3. 每條發現依 P0～P3 判定：
   - P0：修法明確、範圍小、不改商業規則 → 改完走 deploy-runbook 窄範圍部署，回報已上線。
   - P1：小迭代 → 開分支 patrol/<主題>-YYYYMMDD、push、可開 [巡檢P1] PR，不上正式。
   - P2／P3：只寫建議（流程升級附動作流程表草稿），等使用者決定。
4. 假勤政策、獎金切換、全公司 LINE 選單、權限模型、資料表結構 → 一律 P2／P3。
5. 覆寫 TOS/巡檢回報.md 的「本輪」與輪替指針；P2／P3 追加到「待你決定」；
   不要覆寫根目錄 下一輪該改什麼.md。
6. 結尾固定三行摘要：
   P0 已上線：…
   P1 分支待看：…
   待你決定（P2／P3）：…

禁止：假裝六種人格一次講完；複製貼上舊回報交差；沒讀過程式就編造流程。
標準反例（會計視角尤相關）：列表第一次讀取失敗卻顯示成空、無重試、讀表過慢 → 優先當 P0／P1。
```

| 項目 | 建議 |

| 名稱 | 營運系統真人巡檢 |
| 節奏 | 每 2 小時（系統穩定後可改每天一次） |
| 環境 | liff-checkin + Backend_GAS |
