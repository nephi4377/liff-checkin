# 自動化規格管理｜自動化指示（可貼 Settings）

把下面「指示正文」整段貼進 Cursor Automation 的指令／prompt 欄。  
名稱建議：`自動化規格管理`。觸發：**每天 1 次**（或每 6 小時）。環境：多倉庫 **liff-checkin + Backend_GAS**。

這不是倉庫裡的 cron，而是 [Cursor Automations](https://cursor.com/automations)。  
與「營運系統真人巡檢」分開；**不要**覆寫 `TOS/巡檢回報.md`。

> **2026-11-11 測跑後已修**：狀態分支優先、前後端各開 PR、回報最後寫入並附 PR／Slack 連結。若 Dashboard 仍是舊指示，請**整段重貼**本檔「指示正文」。

## 指示正文

```text
你正在執行「自動化規格管理」。必須遵守專案 Skill：automated-spec-manager
（路徑 .agents/skills/automated-spec-manager/；先讀 SKILL.md、phases.md、檢查維度.md、實作備註.md）。

目標：分階檢查功能 → 建立／升級 SPEC；每輪必查（1）交叉出錯（2）易延時（3）可改進；
B0／B1 必發 Slack #程式撰寫。不是真人巡檢：不以修程式／部署為主業；不要覆寫 TOS/巡檢回報.md。

環境：liff-checkin 與 Backend_GAS 都在工作區。前端根目錄不要 npm install。
未明說部署 → 不 clasp、不 upload。

【步驟｜順序不可顛倒】

A. 定階段（只讀狀態，先別改 SPEC）
1. git fetch origin spec-audit/state；checkout 該分支讀 TOS/規格巡檢回報.md（指針真相）。
   若無分支：比 main 與未合併 spec-audit/*／[規格管理] PR，取最新回報。
2. 定本輪階段（無紀錄＝F1）；避開「上一輪已查功能」。依 phases.md 挑 1～2 個功能。
3. 記下本輪功能 ID 後，再 checkout main 開 SPEC 工作分支（見下）。不要在 spec-audit/state 上改 SPEC。

B. 讀碼與三維度
4. 每個功能：讀前端入口＋對應 GAS；再讀既有 SPEC。可並行探索前後端，但結論要合併。
5. 必做檢查維度.md：交叉≥2 情境（已防／未防／不明）；延時低／中／高＋一句；可改進≥1。
   特別盯：失敗當成功、失敗當空、整表掃描、status 成功但訊息才是失敗、文案與狀態機不一致。

C. 升級 SPEC（可前後端同時）
6. 無 SPEC → 合適位置新建；有但落後 → 升級；API／狀態名整段過時 → 寧可重寫該檔主段，勿小修假對齊。
   程式為準；明顯 bug 寫進「已知問題／風險」，不要寫成正確行為。
   建議加「風險與等待」。流程圖：圖內白話、圖下程式對照表。勿寫金鑰／LIFF ID。
7. 功能跨前後端：liff-checkin 與 Backend_GAS **各開**分支與 [規格管理] PR（不要只改一邊）。
   分支名建議：cursor/spec-audit-<階段或主題>-YYYYMMDD-a36f（或實作備註慣例）。
   不上正式、不合 main、不部署。

D. 出錯回報
8. B0／B1 → slack_send_message 到 #程式撰寫（channel_id=C0AULCX9SLT）；同輪可併一則。
   失敗重試一次；仍失敗在回報註「Slack 未送出」。有 B0／B1 沒試 Slack＝本輪失敗。

E. 收工（狀態最後寫｜必做檢查清單）
9. checkout spec-audit/state（必要時從 main 建分支）；覆寫 TOS/規格巡檢回報.md：
   - 本輪階段／功能／SPEC 動作表／交叉・延時・可改進表／Bug 表
   - 「待修／待你決定」累積（勿清空舊列）
   - 「近期 SPEC 更新」列上 **PR 完整 URL**
   - 輪替指針改下一階段；更新時間用 Asia/Taipei
10. git push origin spec-audit/state（指針推進以這裡為準；不要等 SPEC PR 合併）。
11. 可把同份回報再 commit 進各 SPEC PR 分支方便人看，但真相仍是 spec-audit/state。
12. 對話結論＋固定四行：
    SPEC 已更新：…
    Bug 待看：…（B0／B1 註已送 #程式撰寫 或未送出原因）
    延時／交叉／改進：…
    下一階指針：…

【收工自檢｜任一否＝未完成】
- [ ] 下一輪指針已 push 到 origin/spec-audit/state（不是只在 SPEC PR）
- [ ] 回報「近期」有 PR 連結（若有開 PR）
- [ ] 有 B0／B1 則 Slack 已送或註明未送出
- [ ] 跨前後端功能：兩邊 SPEC／PR 都有處理或明示「僅單邊有 SPEC」
- [ ] 未覆寫 TOS/巡檢回報.md、未部署

禁止：一次掃完全庫；沒讀程式就改 SPEC；只改 SPEC 跳過三維度；
在 state 分支堆 SPEC diff；把輪替只留在未合併 PR；把 bug 當正確規格；複製舊回報交差。
```
