# 自動化規格管理｜自動化指示（可貼 Settings）

把下面「指示正文」整段貼進 Cursor Automation 的指令／prompt 欄。  
名稱建議：`自動化規格管理`。觸發：**每天 1 次**（或每 6 小時）。環境：多倉庫 **liff-checkin + Backend_GAS**。

這不是倉庫裡的 cron，而是 [Cursor Automations](https://cursor.com/automations)。  
與「營運系統真人巡檢」分開；**不要**覆寫 `TOS/巡檢回報.md`。

---

## 指示正文

```text
你正在執行「自動化規格管理」。必須遵守專案 Skill：automated-spec-manager
（路徑 .agents/skills/automated-spec-manager/；先讀 SKILL.md、phases.md、實作備註.md）。

目標：分階檢查功能 → 沒有 SPEC 就建立、有就對照程式升級；發現 bug 要可回報。
不是真人巡檢：不要以修程式／部署為主業；不要覆寫 TOS/巡檢回報.md。

環境：liff-checkin 與 Backend_GAS 都在工作區。前端根目錄不要 npm install。
未明說部署 → 不 clasp、不 upload。

步驟：
1. 讀 TOS/規格巡檢回報.md，決定本輪階段（上一輪的下一階段；無紀錄則從 F1 開始），
   並避開上一輪已查的同一功能 ID。
2. 依 phases.md 在本輪階段挑 1～2 個功能。讀關鍵程式（前端頁＋對應 GAS），再找既有 SPEC。
3. 對每個功能：
   - 無 SPEC → 在合適位置新建（見 Skill「SPEC 放哪裡」）。
   - 有 SPEC 但落後 → 升級（程式為準；明顯 bug 不要寫成正確行為）。
   - 已對齊 → 在回報註明即可。
   流程圖遵守 spec-plain-flowchart（圖內白話、圖下程式對照表）。勿寫金鑰／LIFF ID。
4. 發現錯誤／bug → 依 B0～B3 寫進回報；B0／B1 用 Slack DM 通知 U0AUWBQS62G（失敗則註明未送出）。
   可開分支修明顯小 bug，但不上正式、不合 main。標題或說明加 [規格管理]。
5. 覆寫 TOS/規格巡檢回報.md 的「本輪」與輪替指針；B0／B1／待決追加「待修／待你決定」。
   不要覆寫 TOS/巡檢回報.md、不要覆寫根目錄 下一輪該改什麼.md。
6. 對話立刻寫結論；結尾固定三行：
   SPEC 已更新：…
   Bug 待看：…
   下一階指針：…

禁止：一次掃完全庫；沒讀程式就改 SPEC；把 bug 當正確規格寫死；複製舊回報交差。
```
