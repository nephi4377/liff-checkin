# 自動化規格管理｜切換步驟（Dashboard）

給你在 [Cursor Automations](https://cursor.com/automations) 手動操作。

## 1. 確認倉庫已有檔案

在 `liff-checkin` 應看得到：

- `.agents/skills/automated-spec-manager/SKILL.md`
- `.agents/skills/automated-spec-manager/phases.md`
- `.agents/skills/automated-spec-manager/實作備註.md`
- `TOS/規格巡檢回報.md`
- `TOS/自動化規格管理_自動化指示.md`

若雲端 Agent 讀不到，先把這些檔 **commit 並 push 到預設分支**（或先合本 PR）。

## 2. 建立自動化

1. **New Automation**，名稱：`自動化規格管理`
2. 觸發：**Scheduled → Daily**（或 Every 6 hours）
3. 環境：選 **liff-checkin + Backend_GAS**
4. 指示：貼上 [`自動化規格管理_自動化指示.md`](./自動化規格管理_自動化指示.md) 裡的「指示正文」
5. 模型：選文件與讀碼較穩的較強模型
6. 儲存並設為 **Active**

## 3. 測跑一輪

1. 按 **Test run**
2. 跑完檢查：
   - Run History 為 Succeeded
   - `TOS/規格巡檢回報.md`「本輪階段」應為 **F1**（或你插隊的階段）
   - 有 SPEC 新建／升級，或明確「已對齊」
   - 結尾有摘要三行
3. 若有 B0／B1：`#程式撰寫` 是否出現【規格管理・出錯】訊息（或回報註明 Slack 未送出）

## 4. 之後你怎麼用回報

| 狀態 | 你做什麼 |
|------|----------|
| SPEC 已更新（PR） | 看 diff，合進 main |
| Bug 待看 B0／B1 | 決定要不要修、要不要部署 |
| 待你決定 | 回聊天「做第 N 項」或「不做」 |

## 5. 出問題時

- 連續 Failed：環境是否仍掛兩個 repo、指示是否被改短
- 一直查同一功能：看「上一輪已查功能」有沒有寫入
- 誤改真人巡檢檔：確認指示有寫「不要覆寫 TOS/巡檢回報.md」
- 與真人巡檢搶額度：把本自動化改成每天一次即可
