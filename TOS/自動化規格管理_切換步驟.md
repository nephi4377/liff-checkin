# 自動化規格管理｜切換步驟（Dashboard）

給你在 [Cursor Automations](https://cursor.com/automations) 手動操作。

## 1. 確認倉庫已有檔案

在 `liff-checkin` 應看得到：

- `.agents/skills/automated-spec-manager/SKILL.md`
- `.agents/skills/automated-spec-manager/phases.md`
- `.agents/skills/automated-spec-manager/檢查維度.md`（交叉出錯／延時／可改進）
- `.agents/skills/automated-spec-manager/實作備註.md`
- `TOS/規格巡檢回報.md`
- `TOS/自動化規格管理_自動化指示.md`

若雲端 Agent 讀不到，先把這些檔 **commit 並 push 到預設分支**（或先合本 PR）。

## 2. 持久狀態分支（合 PR 後做一次）

輪替指針與「待修」累積在 **`spec-audit/state`**，不依賴 SPEC PR 是否已合。

合進 main 後若遠端尚無此分支，可手動或等首輪 Automation 建立；也可本機：

```bash
git fetch origin
git checkout -B spec-audit/state origin/main
# 確認 TOS/規格巡檢回報.md 已在工作樹
git add TOS/規格巡檢回報.md
git commit -m "chore(spec): seed audit rotation state"
git push -u origin spec-audit/state
```

之後每輪 Automation 開跑前讀此分支、收工後更新此分支。

## 3. 建立自動化

1. **New Automation**，名稱：`自動化規格管理`
2. 觸發：**Scheduled → Daily**（或 Every 6 hours）
3. 環境：選 **liff-checkin + Backend_GAS**
4. 指示：貼上 [`自動化規格管理_自動化指示.md`](./自動化規格管理_自動化指示.md) 裡的「指示正文」  
   （**重要**：Skill／指示若有更新並合進 main，請回 Dashboard **整段重貼**，否則排程仍跑舊步驟。）
5. 模型：選文件與讀碼較穩的較強模型
6. 儲存並設為 **Active**

## 4. 測跑一輪

1. 按 **Test run**
2. 跑完檢查：
   - Run History 為 Succeeded
   - `origin/spec-audit/state` 上的回報「本輪階段」有推進（首輪 **F1**）
   - 有 SPEC 新建／升級 PR，或明確「已對齊」
   - 「交叉出錯／延時／可改進」表有填（不是空白交差）
   - 結尾有摘要四行
3. 若有 B0／B1：`#程式撰寫` 是否出現【規格管理・出錯】訊息（或回報註明 Slack 未送出）
4. 再 Test 一次：確認下一輪階段前進（不是又從 F1 重來）

## 5. 之後你怎麼用回報

| 狀態 | 你做什麼 |
|------|----------|
| SPEC 已更新（PR） | 看 diff，合進 main |
| Bug 待看 B0／B1 | 決定要不要修、要不要部署 |
| 待你決定 | 回聊天「做第 N 項」或「不做」 |
| 看指針／累積 | 看分支 `spec-audit/state` 的 `TOS/規格巡檢回報.md` |

## 6. 出問題時

- 連續 Failed：環境是否仍掛兩個 repo、指示是否被改短或未重貼最新版
- 一直查同一功能／每輪都 F1：是否沒 push／沒讀 `spec-audit/state`；是否在 SPEC PR 上改指針卻沒推 state
- 只有前端 SPEC、後端過時：指示要求跨端功能兩 repo 都開 PR
- 誤改真人巡檢檔：確認指示有寫「不要覆寫 TOS/巡檢回報.md」
- 與真人巡檢搶額度：把本自動化改成每天一次即可

## 7. 測跑後已知升級（已寫進指示／Skill）

- 狀態最後寫、附 PR URL  
- 失敗當成功／文案≠狀態機／清班表字串對不上 → 檢查維度 A9～A11  
- SPEC 整段過時則重寫，不假對齊
