# 營運系統真人巡檢｜切換步驟（Dashboard）

給你在 [Cursor Automations](https://cursor.com/automations) 手動操作。Agent 已備好 Skill 與回報骨架後，依序做：

## 1. 確認倉庫已有檔案

在 `liff-checkin`（本機常對應 CODING）應看得到：

- `.agents/skills/system-human-patrol/SKILL.md`
- `.agents/skills/system-human-patrol/perspectives.md`
- `.agents/skills/system-human-patrol/實作備註.md`
- `TOS/巡檢回報.md`
- `TOS/營運系統真人巡檢_自動化指示.md`（本指示來源）

若雲端 Agent 讀不到，先把這些檔 **commit 並 push 到預設分支**。

## 2. 停用舊看板排程

1. 打開自動化 **「每2小時覆寫升級看板」**
2. 改為 **Paused / Inactive**，或刪除（若你確定不再用）
3. 目的：避免繼續覆寫 `下一輪該改什麼.md`，與新巡檢搶資源

`下一輪該改什麼.md` 可留在倉庫當手動規劃，新排程**不會**再改它。

## 3. 建立新自動化

1. **New Automation**，名稱：`營運系統真人巡檢`
2. 觸發：**Scheduled → Every 2 hours**
3. 環境：選已成功的 **liff-checkin + Backend_GAS**（或同等多倉庫環境）
4. 指示：貼上 [`營運系統真人巡檢_自動化指示.md`](./營運系統真人巡檢_自動化指示.md) 裡的「指示正文」（開頭須有「入口＝系統路徑」；若 Dashboard 仍是舊指示，請重貼，否則排程會誤跟對話裡的 FAQ／案例）
5. 模型：選先前 Run History 穩定 **Succeeded** 的較強模型
6. 儲存並設為 **Active**

## 4. 測跑一輪

1. 按 **Test run**（或等下一個排程）
2. 跑完檢查：
   - Run History 為 Succeeded
   - `TOS/巡檢回報.md`「本輪視角」有值（首輪應為 **總監**，下一輪指針為 **會計**）
   - 結尾有摘要三行
3. 可選第二測：手動把指針改成「下一輪＝會計」再 Test，對照廠商名冊「失敗當空／太慢」是否被抓成 P0／P1

## 5. 之後你怎麼用回報

| 狀態 | 你做什麼 |
|------|----------|
| `已部署`（P0） | 抽空用人話驗收列上的步驟；有問題再說 |
| `分支待看`（P1） | 看 PR／分支，決定要不要合進 main 與上線 |
| `等你決定`（P2／P3） | 回聊天「做第 N 項」或「不做」；可改 `巡檢回報.md` 備註 |

## 6. 出問題時

- 連續 Failed：先看環境是否仍掛兩個 repo、指示是否被改短
- 一直查同一頁：看回報「上一輪已查切入點」有沒有被寫入
- 又開始改 `下一輪該改什麼.md`：確認舊看板自動化已停、新指示有寫「不要覆寫」
